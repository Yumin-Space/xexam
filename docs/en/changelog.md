### v2.3 — 2026-11-21

**AI Chat redesigned like a chat app: a new chat on every visit, a sidebar on tablets and desktops, a drawer on phones, and a tidier top bar. A change to the screens only: no server, database or variable changes. Upgrading: pull the images; rolling back to v2.2 needs no restore.**

- **AI Chat opens a new chat**, on every width. A chat in the address and an answer that is still being written win; a user whose AI+ feature is paused opens their latest chat, read only.
- **Phone layout (under 720 px)**: one header row with the **All chats** button (a two-line menu icon), the title with the **Free mode** tag, a **New chat** button and a **⋯** menu that deletes this chat. A drawer slides in from the left (the smaller of 320 px and 82 % of the screen) with a search box, **New chat**, **Memory**, the history grouped by **Today**, **Yesterday**, **Previous 7 days** and **Older**, a **⋯** menu on every row, **Delete all chats**, the retention note and the GitHub line. It closes when you tap the page behind it, press Esc, swipe left, press the back button or pick an item.
- **Tablets and desktops** show the same sidebar all the time. The **Chats** and **Memory** tabs are gone: **Memory** is a row of the sidebar and its view replaces the conversation.
- **A new empty chat shows a greeting.** The administrator notice is shorter (one line on phones) and is no longer in the drawer. **Jump to latest** only scrolls and never opens the keyboard. The strength button looks the same for every level. A deleted or missing chat in the address resets to a new chat with a short note.
- **Top bar**: the logo icon is back on tablets and desktops; phones show only the word **Xexam**. With a very large text size on a narrow phone the name first gets smaller and is left out only as a last resort.
- **A redesigned message box.** In a new empty chat the greeting and the message box sit in the middle of the screen; after the first message the box docks at the bottom, and the administrator notice always stays at the very bottom. The reply-language hint line under the box is gone, and the box area has no separating line and the same background as the conversation. The box is one compact rounded row (brain, input, send) while it is empty or short and expands to full-width text with a controls row below when the text would wrap or has a new line; it grows up to 8 lines (40 % of the visible height on a phone), then scrolls inside, breaks long words at the edge and shrinks back. On a phone, while the box is one row, the thinking-strength choice is a dropdown inside the brain picker (after API and model); when the box expands, and on wider screens, it is the separate strength button again. **Jump to latest** never opens or closes the keyboard.
- **A new dark theme on every page**: a pure black page (#000000), #212121 cards, inputs, menus and the message box, #303030 controls, white text and white hairlines. The light theme is unchanged, and so are the meaning colours (exam green, practice orange, answer colours, AI+ orange, danger red).
- **Smaller fixes**: the phone top bar fits even with a very large text size (the name shrinks and is left out only as a last resort); Home's start row fits a phone held sideways; the strength menu stays on screen in a short landscape window; the answer-sheet chips are 44 px to tap.

### v2.1 — 2026-11-20

**Thinking strength per connection, the AI Chat picker with a strength step, a light / dark button in the top bar, and a fix for the iPhone menu. Upgrading: pull the images; the AI database moves to schema 11 on start after a backup copy (rollback = restore `backups/xexam-ai-schema10-*.db`); the main database does not change.**

- **Thinking strength follows the connection**: every connection has a **Thinking-strength parameter** (**Anthropic** `output_config.effort`, **OpenAI** `reasoning_effort`, **Google** `thinking_level`, **Responses API** `reasoning.effort`), chosen from the connection's format and address until you pick one by hand. One connection is one family; for a gateway that serves several vendors add one connection per vendor. The connection cards show the family.
- **Model rows**: the **Default** button and the family buttons are gone. Each row shows the family icon of its connection and a level list; an untouched row sends the model's own default level (unknown model: `medium`), so every call carries a strength. A model that rejects the parameter no longer stops it for the other models of that connection.
- **Master switch**: while AI+ is off, every model row is greyed and cannot be changed (switches show off, stored choices are kept); turning AI+ on shows them again.
- **AI Chat picker**: administrators in free mode now choose **API**, then **Model**, then **Strength** (the levels of that connection's family, the model default marked). The choice is remembered per chat; the brain button shows a dot for a non-default strength.
- **Top bar**: a moon / sun button left of your name switches between the dark and the light look and saves the same choice as **Settings → Appearance**.
- **iPhone menu fix**: with a conversation open in AI Chat, a tap on a menu item no longer left you in AI Chat. Menu items also show a pressed shade while tapped.

- **Pacing used as entered**: the provider rate limit is no longer reduced by a hidden 10 %. New defaults are 13 requests and 240 000 tokens a minute. On upgrade, stored values on the old defaults (15 / 250 000) become 13 / 240 000 and others are multiplied by 0.9 (at least 1 and 1 000), so the pace stays the same.
- **Database, AI (schema 10 to 11)**: new `connections.effort_family` (inferred from provider, format and model names; one log line per connection) and `chats.pick_effort`. Stored slot strengths that do not fit their connection's family are cleared (the model default is used). A backup copy `backups/xexam-ai-schema10-<date-time>.db` is written first. Details: section 8.2h of [database.md](database.md) and the v2.0 to v2.1 section of [migration.md](migration.md).
- **Going back**: a v2.0 ai-service refuses schema 11: restore `backups/xexam-ai-schema10-<date-time>.db` into the AI volume (settings, chats and usage written after the upgrade are lost). The main database needs no restore.

### v2.0 — 2026-11-20

**Database clean-up: foreign keys in the main database, legacy tables and columns removed, new indexes; no visible change in the app. Upgrading: pull the images; both databases move to a new schema on start, each after a backup copy (main 10 to 11, AI 9 to 10); keep about twice the size of the main database free. Going back to v1.9 needs the AI backup `backups/xexam-ai-schema9-*.db`; the main database needs no restore.**

- **Database, main (schema 10 to 11)**: nine tables (`banks`, `questions`, `imports`, `attempts`, `attempt_items`, `sessions`, `user_stats`, `user_settings`, `user_banks`) are rebuilt with foreign keys (all `ON DELETE NO ACTION`; the code already deletes child rows first). The links to `attempt_items.question_id`, `user_stats.question_id`, `activity_log.user_id` and `system_settings.updated_by` are left out on purpose (records outlive questions and accounts; a link on `updated_by` would block deleting an administrator who once changed a site switch). Rows that point to nothing (orphans) are removed or detached by fixed rules, counted and logged. The unused legacy tables `stats` and `settings` are dropped (their rows were copied in v0.6). New indexes: `idx_user_stats_question`, `idx_imports_bank`, and a unique index on `users.uid` (skipped with a warning if two users share a stamp; nothing is changed then). No column, value or screen changes. A backup copy `backups/xexam-schema10-<date-time>.db` is written first; the whole step is one transaction that rolls back on any surprise (row counts are compared and a foreign-key check runs before it is committed).
- **Database, AI (schema 9 to 10)**: the table `secrets` (old provider keys), ten old single-connection columns of `settings`, five old length columns of `limits` and `chats.free` are dropped; nothing reads them any more. The upgrade happens in one transaction after the copy `backups/xexam-ai-schema9-<date-time>.db`, and the old key copy is wiped from the live file (the backup copy still holds it: keep it private or delete it). The log says how many rows and columns were removed, never their content.
- **Upgrading**: `docker compose pull`, then `docker compose up -d`. Keep about twice the size of the main database free (the backup plus the rebuilt tables); with a large history of study records the first start can take longer, and the server listens only after the upgrade is done. Details: section 6.17 of [database.md](database.md) and the v1.9 to v2.0 section of [migration.md](migration.md).
- **Going back**: a v1.9 backend opens the schema-11 main database as it is (no restore; if v1.9 re-creates an empty `stats` table, v2.0 drops it again). A v1.9 ai-service refuses schema 10: restore `backups/xexam-ai-schema9-<date-time>.db` into the AI volume (settings, chats and usage written after the upgrade are lost). Anything older than v1.9 needs the main backup too.

### v1.9 — 2026-11-20

**A clearer AI settings page (connection on/off switches, one switch per feature, seven safety sub-tabs), provider rate-limit pacing for AI generation and import, a model picker in AI Chat, language choice in bank download, and the three services can run on different machines. Upgrading: pull the images; the AI database moves to schema 9 on start with a backup copy (rollback = restore `backups/xexam-ai-schema8-*.db`); compose: no required change for one host; new optional variables `XEXAM_FRONTEND_PEERS`, `XEXAM_INTERNAL_TOKEN_REQUIRED`, `XEXAM_BACKEND_UPSTREAM`, `XEXAM_AI_UPSTREAM` and `XEXAM_NGINX_RESOLVER`, and three per-machine compose files. The main database does not change.**

- **User-Agent towards AI providers (default changed)**: `XEXAM_AI_USER_AGENT_NAME` unset, empty or blank now sends `xexam-ai-service/<version>` again (v1.8 sent none). The value `none` (any case) sends no `User-Agent` header at all, which is the v1.8 behaviour and the way to keep the app name away from a gateway. Any other printable ASCII value (at most 256 characters) is sent as is; an invalid value gives one warning at start (the value is never printed) and the default is sent. Requests to the backend and the IP-location lookup are unchanged.
- **Home: AI summary button** (**Latest result**): the AI summary button now has the same flat amber look as the other AI actions (white bold text on amber, the same in light and dark; on a phone an amber icon button). When it cannot be used it looks like the greyed **AI generate** button with the **Unavailable** tag. No new colour.
- **AI Chat model picker**: administrators in free mode get a small popover with two selects: **API** (connection) and then **Model** of that connection. It starts on the chat's remembered choice, otherwise on the AI Chat default; picking the model marked **(default)** means "follow the default". Changing only the API changes nothing that is sent. The thinking-strength control is not in the picker.
- **Connection on/off switch** (AI settings → Connections and models): every connection has a switch. Off keeps all its settings, key and models, but the connection leaves every picker and all routing. A feature, default or chat that points to an off connection keeps its choice and fails with a clear message (`ai.connectionOff`, HTTP 409); there is no fallback and nothing is dropped silently. New and existing connections start on. The status chip reads **On · working** (green) or **Off** (grey), and the list is two collapsible groups, **Enabled connections** and **Connections not enabled**, both collapsed at first (the open state is remembered for the browser session). Turning a connection off asks for confirmation and names the features that use it. Switching does not cancel running calls; **Test** still works on an off connection.
- **One switch per feature, administrators included**: the separate feature-switch section is gone. Every model row except **Default** carries its own switch, and a switched-off feature is off for everyone, administrators included (the chosen model is kept and the row's pickers are disabled). The old **Study** row is split into **Hint** and **Analysis** (analysis also serves result and record analysis): on upgrade both start with the old study model and thinking strength. The global switches are independent now (hint and analysis are no longer paired); the per-user boxes in User management still pair hint and analysis.
- **Gemma thinking-strength family removed**: the **Gemma** button is gone. A stored Gemma choice is rewritten on start to the Google family with the same request (`HIGH` and `true` become Google `HIGH`; `MINIMAL` and `false` become Google `MINIMAL`; anything else is cleared). The API refuses the family `gemma` (400). Use **Google** `HIGH` / `MINIMAL` for Gemma 4.
- **Provider rate-limit pacing** (AI safety → Server): one global setting for AI generation and AI import calls, **on** by default, with **15 requests** and **250,000 tokens** a minute (what a typical free tier allows). About 90 % is used (13 requests and 225,000 tokens a minute), requests are spread evenly (one about every 4.6 s) over a sliding 60-second window, the tokens of each call are estimated before it is sent, and fewer calls run at once when needed. It is independent of the **Unlimited** switches. A provider answer of "rate limit" (HTTP 429) is waited out for the time the provider names and retried (up to 10 times per call, not counted as an error, also with pacing off); a daily quota stops the job with a clear message and no charge. While a job waits for 8 seconds or more it shows **Waiting for the provider's quota…**. For a limited (non-unlimited) job the waiting counts against its 30-minute deadline.
- **AI safety split into seven sub-tabs**: **Limits**, **Chat**, **Hints and analysis**, **Summary**, **AI generation**, **AI import** and **Server**. The sub-tab is in the address (`#/ai-settings?tab=safety&sub=<name>`); opening the tab without one returns to the last sub-tab used in this browser session, else **Limits**. **Save** sends every changed value of the whole form; **Reset** resets only the sub-tab you see.
- **Bank download: choose the languages**: the dialog has **中文**, **English** and **日本語** checkboxes above the format buttons, all ticked, at least one required (not remembered). Excel keeps all six columns in place and leaves the cells of unticked languages empty (without English the file cannot be imported again; the dialog says so); Word holds only the ticked languages, English first, then Chinese, then Japanese. With all three the file name is unchanged; otherwise it ends with the codes, for example `Garden_en-zh.docx`. The endpoint takes the optional `langs=en,zh,ja` (missing = all three; anything else is 400) and the activity log records the languages.
- **Services on different machines**: the frontend, backend and ai-service can run on three machines. The frontend image reads `XEXAM_BACKEND_UPSTREAM`, `XEXAM_AI_UPSTREAM` and `XEXAM_NGINX_RESOLVER` (defaults unchanged); the backend and ai-service read `XEXAM_FRONTEND_PEERS` (an allow-list of the frontend's addresses; unset = any peer, as before; others get `404`, and forwarded client headers are trusted only from listed peers) and `XEXAM_INTERNAL_TOKEN_REQUIRED=1` (refuse to start without a valid `XEXAM_INTERNAL_TOKEN`). `XEXAM_AI_BACKEND_URL` now accepts `http://` or `https://`. Three new files, `docker-compose.frontend.yml`, `docker-compose.backend.yml` and `docker-compose.ai-service.yml`, are the per-machine versions; the one-host compose files are unchanged. Section 12 of [deployment.md](deployment.md).
- **Database**: AI schema 8 to 9 (`connections.enabled`, the three pacing columns in `limits`, `model_slots` rebuilt with `hint` and `explain` instead of `study`), with a backup copy `backups/xexam-ai-schema8-<date-time>.db` first. v1.8 refuses schema 9: to roll back, restore that copy. Sections 8.2f and 9 of [database.md](database.md) hold the details and a schema map of both databases.

### v1.8 — 2026-11-16

**Requests to AI providers no longer carry a User-Agent naming Xexam, and a gateway connection can now use the OpenAI Responses API. Upgrading: pull the images; one optional compose variable (`XEXAM_AI_USER_AGENT_NAME`); the AI database gets one column on start, with no backup copy and no settings change.**

- **No User-Agent towards AI providers**: every request that ai-service sends to an AI provider or gateway (chat, hints, explanations, summaries, generation, import, model lists and connection checks) now goes out without a `User-Agent` header. Before, it said `xexam-ai-service/<version>`, so the gateway and every service behind it could see the app name and version. The name of the structured-output schema sent to OpenAI-compatible providers is now the neutral `answer` (was `xexam_answer`). Requests between ai-service and the backend inside the stack still say `xexam-ai-service/<version>`, and so does the external IP-location lookup.
- **New optional variable `XEXAM_AI_USER_AGENT_NAME`**: unset or empty (the default) keeps the behaviour above, no `User-Agent` at all. When set, its value is sent as is as the `User-Agent` of every request to AI providers and gateways, for example a name your own gateway recognises. Printable ASCII, at most 256 characters; an invalid value is ignored with one warning in the log (no header is sent). It never changes the requests to the backend inside the stack or the IP-location lookup.
- **New gateway connection format "OpenAI Responses"**: a Cloudflare AI Gateway connection can now use the OpenAI Responses API (**API format**). Chat goes to `POST {address}/responses`, the model list is `GET {address}/models`, and the provider key goes in `Authorization: Bearer` like the OpenAI format (so the gateway key and a provider key clash the same way: choose `cf-aig-authorization`, or remove the provider key). It is picked by hand only: the format is never filled in from the address, and the OpenAI-compatible provider type stays chat completions. Structured output is sent as `text.format`; the **Responses API** family of the thinking strength sends `reasoning.effort` natively; the answer limit is `max_output_tokens`; no cache markers are sent (OpenAI caches automatically) and the cached tokens are read from `input_tokens_details`.
  - **Database**: the AI database gets one column, `connections.responses`, added on start. There is no schema change and no backup copy. Rolling back to v1.7 needs no restore, but a Responses connection then reads as OpenAI chat completions.

### v1.7 — 2026-11-16

**One broken question no longer costs a whole AI generation or import call, and the thinking-strength level starts at the model's own default. Upgrading: pull the images; nothing else changes (no database, settings or compose change).**

- **AI generation and AI import keep the readable questions**: the model sometimes leaves out the `"options":[` key after a question's stem, which used to make the whole answer unreadable and threw away every question of that call (usually 5). That slip is now repaired automatically. When an answer still does not parse as a whole, each question in it is read on its own: the readable ones are kept and only the broken one is written again. An answer that is really cut off still counts as cut (the questions-per-call rule is unchanged).
- **Thinking strength**: when you pick a family button in AI settings, the level starts at the model's own known default if that family has it (otherwise as before).

### v1.6 — 2026-11-16

**Bank download as Excel or Word, thinking strength per AI feature, steadier AI generation and import, and places filled in for old sign-ins. Upgrading: pull the images; the main database moves to schema 10 automatically after a backup copy; the AI database stays at schema 8 (one column is added by itself).**

- **Bank download** (Question banks): every bank row has a **Download** button that opens a dialog with **Excel** and **Word**. **Excel** is the six-column import layout with one worksheet per sheet, so downloading a bank and importing the file again gives the same questions. **Word** holds the title, then **English**, **Chinese** and **Japanese**, each on a new page and each with every sheet: built-in heading styles, the correct options marked, the answer, the explanation, the mnemonic and the note. Retired questions are left out. Administrators always may; a plain user needs the new **Download banks** right, set per user in the bank dialog of **User management** (right after **Manage banks**; **Select all** / **Deselect all** moved to the right end of that row; off by default), and gets only the banks they can see, on a page that shows the bank list and nothing else. The server enforces the right (`GET /api/banks/download?id=<bank>&format=xlsx|docx`, 403 without it) and writes `bank.download` to the activity log. Section 11.1 of [usage.md](usage.md).
- **Thinking strength per feature** (AI settings → Models): above the provider and model pickers of each feature a row of buttons, **Default**, **Anthropic**, **OpenAI**, **Google**, **Responses API** and **Gemma**, and a list of levels; a change is saved at once. **Default** sends nothing, so the model uses its own default. The level names are always shown in English, as they are sent, in every language, and hovering, focusing or touch-and-holding a button shows the request parameter it sets: Anthropic `output_config.effort` (low, medium, high, xhigh, max), OpenAI `reasoning_effort` (low, medium, high, xhigh, max), Google `thinking_level` (MINIMAL, LOW, MEDIUM, HIGH, XHIGH; sent as `extra_body.google.thinking_config.thinking_level`), Responses API `reasoning.effort` (none, minimal, low, medium, high, xhigh, max) and Gemma `thinking_level` (HIGH, MINIMAL; Gemma 4 on Google AI Studio accepts only these two, and MINIMAL turns thinking off). Any button works with any connection. When a provider refuses a request that carries the parameter (HTTP 400 or 422), it is sent once more without it and the connection is remembered as not supporting it (until ai-service restarts or the setting changes). A grey line shows the model's own default where it is documented. Section 17.9 of [usage.md](usage.md); the choice is stored in the AI database (`model_slots.effort`) and every change writes `ai.settings.effort` to the activity log.
- **Structured AI answers**: generation and import now ask the provider for structured output (Anthropic `output_config.format` with a JSON schema, OpenAI-compatible `response_format` with a strict JSON schema) and fall back to the plain request when a provider refuses it (remembered per connection until ai-service restarts). Every question names its correct options once, as letters in an `answer` field, and the program sets the option flags from it; the old per-option `correct` form is still read, and an option without `correct` counts as false when another option is true.
- **Room for thinking, no more shrinking questions per call**: the token budget of a plan call is the smaller of 22 000 and 6 200 + 90 × questions (20 questions give 8 000), and the global plan has 8 000, which leaves room for the model's own thinking. The number of questions per call now shrinks only when an answer was really cut, so a job no longer slides from 5 to 3 to 2 to 1 question per call.
- **AI settings**: the **Connections and models** tab is ordered connections, AI+ switch, feature switches, models. **AI usage** charts (by model, by feature, over time) show tokens by default; the **Calls | Tokens** choice is remembered per user in that browser.
- **Places for old sign-ins**: after the location source is switched to the **external lookup API**, or new provider settings are saved while it is the API, the backend looks up again every stored address whose records have no place (any age: **System log** rows, last sign-in and last activity), one lookup per distinct address, live lookups first, 30 a minute; a rate-limit answer pauses it for 15 minutes and an address is tried at most 3 times. Existing places are never overwritten. It stops when the eye is turned off, the source goes back to Cloudflare, or the records are cleared. In Cloudflare mode the **System log** rows that ai-service writes now carry the Cloudflare place as well (Nginx passes `X-Geo-*` to ai-service, from trusted proxies only). The **On** / **Off** switch of the sign-in IP and location eye now asks for confirmation both ways. Section 14.2 of [usage.md](usage.md).
- **AI import drop box**: it shows the size limit (**max 20 MB**, the configured value).
- **Database**: main schema 9 to 10 (one column, `users.can_download_banks`, default off), with a backup copy `backups/xexam-schema9-<date-time>.db` first; the AI database stays at schema 8 (the column `model_slots.effort` is added on start, no backup copy is needed). Rolling back to v1.5 needs no restore. Section 00000 of [migration.md](migration.md).
- **CI**: the x86 frontend image is built on its own and the Nginx test starts as soon as it is ready; end-to-end waits for all three x86 images; publishing still waits for every check.
- **Upgrading from v1.5**: pull the images (no new `docker-compose.yml` variable). The new `nginx/snippets/ai-proxy.conf` is part of the frontend image.

### v1.5 — 2026-11-15

**CI only: no change to Xexam itself; the images are the same as v1.4 apart from the version number. Upgrading: nothing to do (pull the images if you want the new version number).**

- **Native ARM builds**: the arm64 check and the published arm64 images are now built and started on GitHub's own ARM runners instead of being emulated with QEMU on x86; the amd64 images are built on their own runner in parallel, and the two are joined into one multi-arch image per tag (`latest`, `v1.5`, `sha-<commit>`) on Docker Hub and ghcr.io.

### v0.3 — 2026-11-10

**The whole program was rewritten in Rust + TypeScript + Nginx. The database file and schema are unchanged, the API is backward compatible, and the old Python implementation has been removed from the repository.**

- **Backend rewritten in Rust** (Axum 0.8 + Tokio + rusqlite, toolchain pinned to 1.99.1): REST API, XLSX parsing, import (preview without writing to the database → one-time confirmation token → one-transaction write), score and wrong-answer statistics, Host/Origin guard, and the `xexam-backend import / healthcheck / migrate-progress` subcommands. Behavior matches the Python version one to one: all 172 legacy responses were compared item by item with no unexplained differences; the parse output of 49 synthetic workbooks and all 85 question id vectors are identical, so question ids are byte-for-byte the same as in the old version and learning records do not become detached.
- **Frontend rewritten in TypeScript** (strict) + **Vite**, plain DOM, no framework; there are no inline styles, so the CSP can be very strict. The build target is `safari15`, so iPhone needs iOS 15.4 or later.
- **Two images, two containers**: `xexam-frontend` (Nginx + static frontend files, the only one exposed) and `xexam-backend` (Rust, on the `internal` private network with no published port). Non-root, `cap_drop: ALL`, read-only root filesystem; Host passed through unchanged, `X-Forwarded-*` cleared; 20 MB limit, security headers, rate limiting, timeouts; a JSON 502 is returned when the backend is unreachable. Both images ship for `amd64` and `arm64`.
- **Stricter upload checks (intentional differences)**: DOCTYPE and entity declarations are rejected in any encoding / extension; duplicate ZIP entry names are rejected; there are limits on the number of ZIP entries, XML depth / node count / attributes per element, and total cell bytes; parsing has a cooperative timeout (the parser stops by itself when time is up) and at most 2 parses run at the same time; error messages no longer echo the library's exception text; unsupported HTTP methods return 405 (previously 501). See [docs/en/api.md](api.md) for the full table of differences.
- **One pipeline** (`.github/workflows/ci.yml`): check version and changelog → four check groups (frontend / backend / Nginx and full stack / arm64) → only if all pass, publish the two images and create the Release.
- **Tests**: 136 backend tests (against the committed legacy snapshot: 172 golden responses, 49 parse fixtures, 85 id vectors), 19 frontend tests; in `tests/integration/`, 38 Nginx checks, 34 full-stack checks and 10 `progress.json` migration checks.
- **Documentation**: architecture, API (including OpenAPI), database, security, deployment, migration and development under `docs/`, plus the pre-migration audit, risks and plan.
- Grading is still done in the browser (the server only receives `{id, correct}`, i.e. the question id and whether it was answered correctly); the reasoning is in [docs/zh-CN/history/migration-plan.md](../zh-CN/history/migration-plan.md).
- ⚠️ **Upgrade note**: the old and new containers have the same names and ports and **cannot run at the same time**, so run `docker compose stop` before upgrading; the data volume `xexam_data` is the same one, so no data migration is needed. The old single image `ghcr.io/yumin-space/xexam` is no longer updated (the last version was `v0.2.2`), and `docker-compose.yml` now pulls both `xexam-frontend` and `xexam-backend` at once. For rollback steps see [docs/en/migration.md](migration.md).
- **What has not been verified (stated honestly)**: a real Cloudflare Tunnel, a real iPhone, running on real ARM hardware (it was only built and started under QEMU), and a dry run with a copy of your own real database.

### v0.2 — 2026-11-10

- **Can be reached from the internet through your own domain** (Cloudflare Tunnel + Cloudflare Access):
  - Allowed domains go into `XEXAM_ALLOWED_HOSTS`; the `Origin` of write requests is now compared by hostname only, so uploads and submitting a quiz are no longer blocked with 403 when accessed through an **HTTPS** domain.
  - When a proxy rewrites `Host`, `XEXAM_ALLOWED_ORIGINS` can be used to allow the public domain separately; when authentication is already in front, `XEXAM_ALLOW_ANY_HOST=1` can be set.
  - When a request is rejected, the message explains which check failed and how to allow it; when the login expires, the page prompts you to refresh and log in again.

- CI: split into three steps, "check version and changelog → test each of the two architectures → publish" (from v0.2.1 a fourth step is added: create the Release); the smoke test moved into `scripts/smoke-test.sh`, which can also be run directly on a machine with Docker installed; after publishing, the image manifest is verified by digest.
- `/api/info` gains `arch` (the current CPU architecture).
- Fixes after the audit (each one has a corresponding real test):
  - Server: requests rejected early (403/415) have their body read before the reply, so the browser sees the real reason instead of `连不上服务` ("cannot connect to the service"); a rejected request leaves one line in the log (visible with `docker compose logs`); malformed JSON (a number where a list is expected, `Infinity`, over-deep nesting, a non-ASCII confirmation token) returns 400/409 instead of dropping the connection; the `Content-Type` of a POST must really be `application/json`; `XEXAM_ALLOWED_HOSTS` separated by spaces or semicolons is also recognized.
  - Database: if `COMMIT` fails it rolls back instead of leaving the connection stuck in a transaction; a malformed old `progress.json` no longer keeps the program from starting; when the data directory contains only some other `.db` file, the startup log gives a warning (that file is not modified).
  - Pages: when submitting a quiz, the saved progress is cleared only after the score has been submitted successfully; on failure it is kept and a prompt `刷新页面重新登录后再交卷` ("Refresh the page, log in again, then submit") is shown; before starting a new exam, if there is an unsubmitted exam, it asks for confirmation first; the percentage on the result page uses the same rounding as the learning record and no longer differs by 1; the notification bar is no longer covered by the bottom paging bar; long English strings no longer cause a horizontal scrollbar; old Safari without `<dialog>` uses the system confirmation box; holding down a letter key no longer toggles the answer repeatedly.
  - Images and CI: the health check bypasses the proxy and follows `XEXAM_PORT`; `.dockerignore` now applies at any directory level; `.gitignore` gains backup archives and `.env.*`; publishing happens only from `main`, and queued runs on `main` are not cancelled; the in-container paths in the smoke test also work in Git Bash on Windows.

The key names used for the saved exam and the language choice in the browser also changed, so submit your quiz before upgrading; the language will revert to Japanese.
