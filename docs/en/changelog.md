### v0.9.1 — 2026-11-12

**Regenerate now really writes a new answer, and a few small fixes. Upgrading: nothing to do besides pulling the new images (no database change).**

- **Regenerate writes a new answer**: before, an AI gateway that caches responses could return the same answer again in a fraction of a second. Now a regenerate (AI hint, AI explanation, AI analysis, AI summary) and AI Chat's **Retry** add a numbered note to the end of the request (not saved, and not shown in AI Chat), so every attempt is a new request; Cloudflare AI Gateway also gets `cf-aig-skip-cache: true`. A first ask may still be answered from the gateway cache.
- **Hint check**: a hint that contains `<think>` / `<thinking>` tags (the reasoning text of some models) is hidden too.
- **Changelog moved**: from the three READMEs to `docs/<lang>/changelog.md` (the READMEs link to it); the About page and the Release notes read it there, and CI checks the three files.
- **About page**: it no longer shows an HTML comment at the end of v0.1.
- Tests: backend 382 → 382, frontend 391 → 391, AI service 369 → 383

### v0.9 — 2026-11-11

**AI help while you study, for accounts with the AI+ feature: hints and explanations in practice, AI analysis of results and AI summaries of your wrong answers. The three images, the volumes and docker-compose.yml stay as they are. The databases upgrade automatically (main database to schema 6, AI database to schema 3), each after a backup copy is written.**

- **Who sees it**: only accounts that have the **AI+ feature** (administrators while the AI+ feature is on; the orange **AI+** badge). Users without it see none of the controls below. A user who has the feature but cannot use AI now (an administrator paused it, the AI+ feature is off or ai-service is not connected) sees the controls greyed out with an **Unavailable** tag, a tooltip that gives the reason (a tap shows it on a touch screen) and, on Study records, one note above the table. The server refuses these requests too. During an exam there is nothing of this; an exam gets AI only on its result page and in its study record.
- **Practice**: on every question two buttons in the action bar, **AI hint** and **AI explanation**, and the same two as a light-bulb and a book icon in the card header, next to the language switch. Buttons and icons do the same thing.
  - **AI hint**: how to approach the question and the knowledge points behind it, without saying which option is right. The request to the model never contains the answer, and a hint that gives the answer away anyway is hidden (**This hint gave the answer away, so it was hidden. Regenerate to get a new hint.**); that check is a safeguard that catches most, not every, way of saying it.
  - **AI explanation**: the correct answer first, the knowledge the question tests, why it is right and why each other option is wrong.
  - The answer streams into a small closable window next to the button (Esc, a click outside, **Close** or moving to another question closes it) with **Copy**, **Regenerate** and **Open in AI Chat**. Opening the same one again shows the saved answer at once; **Regenerate** writes a new one, and a new one that fails or is hidden leaves the previous answer in place. The answer is in the **Settings** language (a saved answer in another language says so).
- **Results**: every question card of a practice result, an exam result and a study record's detail page has **AI analysis** (a button on the verdict line and a book icon in the card header). It explains the question and, when you got it wrong, discusses your own answer. Its question text follows the card's own language switch.
- **AI summary** of a record, on **Study records** (a new first column, one button per row) and on **Home** (in the latest result, between **View details** and **All study records**): a large window with the weak knowledge points, what to watch out for, how to approach such questions from now on and a simple summary of those topics. Only questions answered wrong count (unanswered ones do not), at most 70, chosen at random when there are more; the window says, for example, **Based on 70 of 80 wrong answers, chosen at random.** **Regenerate** writes a new summary, and pressing the button again shows the saved one. A record with no wrong answers, or one saved by a version that kept no per-question details, has the button greyed out with the reason.
- **One answer at a time**: while one answer is being written, another request says which one (**AI hint for question 3 is still being written.**) and offers **Show it** (when it is on the same page) and **Stop it and write this one**; nothing is stopped by itself. Study answers share this place with AI Chat.
- **In AI Chat**: every practice, exam and summary has one chat, titled `<start time>-Practice`, `<start time>-Exam` or `<record time>-AI summary` (the title words follow the interface language, the times the time zone of ai-service). Every answer goes into it in order, each question marked as a hint, explanation or analysis of question n; the hints and explanations of the practice page and the analyses of its result page share the practice's chat. Study answers have no **Retry** and **Remember this**. Deleting a study record keeps its summary chat. Like every chat, study chats follow the retention period, can be deleted by the user and are visible to administrators; the answers of a deleted chat are no longer offered as saved.
- **Records made before v0.9** have no session key, so the first AI analysis of such a record on its detail page starts a chat of its own, titled with the record's time and the suffix of its type.
- **Data sent to the AI provider**: for a hint, the question and its options in the language shown; for an explanation or analysis also the bank's answer and explanation and, on a result page, your own answer; for a summary the same for each wrong answer. Memory notes, earlier chats and free mode play no part in these requests. Usage is counted by feature (**By feature** under **Usage** in AI settings: AI Chat, AI hint, AI explanation, AI summary), never with content.
- **Limits**: starting a study answer counts against the same Nginx limit as AI Chat (20 a minute per signed-in browser after a burst of 10; the window then says to wait a few seconds). Each study chat counts as a chat and each ask as two messages, so the default 400 messages per chat allow about 200 asks in one long practice (an administrator can change it).
- **Layout**: on a phone the action bar stays at two rows (the two AI buttons keep short labels, and only their icons on very narrow screens), the greyed controls wrap with the language switch instead of widening the page, and Study records keep their card layout on narrow windows, with the AI summary button in each card.
- **Database schema 6** (main database): `attempts.session_key` and `attempts.started_at`, nullable; a copy is written to `<data dir>/backups/xexam-schema5-<date-time>.db` before the migration. **AI database schema 3**: `chats.kind`, `ref` and `record_id`; `messages.kind`, `question_id`, `question_no`, `source`, `lang`, `sample_used`, `sample_usable` and `sample_wrong`; `usage.purpose` (empty for AI Chat); three indexes; a copy is written to `backups/xexam-ai-schema2-<date-time>.db` in the AI volume first. The backups are never deleted automatically, and each upgrade needs free disk space of about the size of its database. v0.8 opens the schema-6 main database unchanged, but its AI service refuses schema 3: rolling back the AI database means restoring its copy. The AI service now deletes chats past the retention period in small batches.
- **New API**: `POST /api/ai/study/ask` and `POST /api/ai/summary/ask` (server-sent events, like `send`), `GET /api/ai/study/saved` and `GET /api/ai/summary/saved`; `kind` and `recordId` on chats and `kind`, `questionId`, `questionNo`, `source`, `lang` and `sample` on messages in the chat routes, `chatKind` in the `start` event, `running` in the `ai.busy` refusal and `byPurpose` in the AI usage; `POST /api/attempt` takes `key` and `startedAt` and answers with the new record's `recordId`, and `GET /api/record` returns `sessionKey` and `startedAt`; the internal `POST /internal/ai/question`, `/record` and `/record-info` (token only). Nginx logs the path of a request but no longer its query string.
- **Releases are signed**: the release job now records the released version (`RELEASE_VERSION` and the README badge) with a commit made through the GitHub API instead of `git push`, so GitHub signs it and it shows as **Verified**.
- Tests: backend 342 → 382, frontend 246 → 391, AI service 160 → 369

### v0.8 — 2026-11-11

**AI Chat in a container of its own, called ai-service, a new icon and more compact bank-access controls. AI is off until an administrator sets it up. Download the new docker-compose.yml: it adds the third image xexam-ai-service and two volumes. The database moves to schema v5 automatically, after a backup copy is written.**

- **AI Chat** (menu): chat with an AI model.
  - Answers stream in as they are written (**Thinking…** shows while a reasoning model is still thinking) and keep being written and saved when the page is closed; **Stop** and **Retry**. Chats are saved and deleted automatically 90 days after their last message (adjustable).
  - The AI answers in the language chosen in **Settings** (unless you ask for another language in that message); memory notes are written in it too. An empty new chat says in which language the AI will answer.
  - A fixed-height window like a chat app: the messages scroll inside it (a region you can reach and scroll with the keyboard) and the message box stays at the bottom. Every message shows its time and has **Copy**; **Remember this** and **Retry** sit on one line under it.
  - The address keeps the open chat: `#/ai/<id>` for a chat and `#/ai/new` for a new one, so a reload opens the same chat again.
  - **Memory** holds short notes the AI uses in later chats, added by hand or with **Remember this**. A line at the top says that administrators can view and delete your AI chats and memories and see your AI usage. You can always read and delete your own chats and memories, also while the AI+ feature is off for you or paused.
  - When you cannot use AI and have no chats or memories, **AI Chat** still opens and says why (paused, the AI+ feature not available right now, or not given to your account) and what to do. The line at the top of a read-only AI Chat is the same sentence as the tooltip of the dark **AI+** badge.
  - **Free mode** is a mode of the administrator, chosen in **Settings** under **AI chat mode** (**Normal** / **Free**; shown only to administrators while the AI+ feature is on). While it is on, every message in any chat, old or new, goes to the model without the study-assistant instructions, today's date and memories (only the reply-language rule stays; the provider's own safety rules always apply), and a green **Free mode** tag sits beside the **AI Chat** title. AI Chat itself has no switch and no dividers. The server keeps the choice, so it survives reloads and other devices; it applies from the next message and is off by default. Every message records the mode it was written in, and after a switch the model is told the current mode in one short line. Limits, usage statistics and the administrators' views apply as usual.
  - **Cheaper requests**: the provider may cache the start of each request (Anthropic: cache points on the instructions and on the history before the new question; OpenAI-format providers cache by themselves where they support it). To keep that start stable, the history is shortened the same way every time: the newest 4 messages in full, older answers cut to 800 characters and older questions to 2000.
- **AI settings** (administrators):
  - the page always opens. At the top four chips show where the set-up stands (**Connection saved**, **Model saved**, **Test passed**, **AI+ feature on**), and a line says whether ai-service is connected (version, last report). On a fresh install the first chip reads **Connection not set** and no model list is requested until you save a connection (saving only the chat retention does not count as one). When ai-service is not connected, a **Connection to ai-service** panel names the cause (not running, stopped, not connected, waiting for its first report, or the main service) and checks again every 10 seconds;
  - an OpenAI-compatible API, Anthropic or Cloudflare AI Gateway (with its auth scheme and key); the models are listed automatically after saving, in a searchable list. Models that are probably not chat models (embedding, reranking, safety classifier, image generation, speech, document parsing, vision only) come last with a tag and a hint; none is hidden. Key fields have a **Show key** / **Hide key** button;
  - the **AI+ feature** can be switched on only after a successful **Test**. Saving a changed connection or model while it is on first asks, then switches it off for everyone, and it stays off until a new test has passed and you switch it on again (a passed test never switches it on by itself; the line under **Test** follows the switch). The keys are stored encrypted and never shown again, and a saved key is never sent to a new address without being entered again;
  - usage statistics by user, model and period (7 days by default; calls, tokens in and out, **Cached** tokens that the provider served from its cache, and errors, never content);
  - **Users with AI+** (everyone who has the AI+ feature): the **AI+ feature** column with **Active** or **Paused** and the buttons **Pause** and **Resume** (they never change the switch in User management), and a read-only view of their chats and memories, which can be deleted with **Delete**; every view, delete, pause and resume is written to the System log. Below 900 px the two token columns are left out (they are in **Usage**); below 560 px each user is a small card;
  - chat retention (1 to 3650 days) and **Safety limits** (answers at once, chats, messages, memories, message length), which protect the server and are not usage limits.
- **One name, two places per user**: the **AI+ feature** is the name everywhere. An administrator switches it on for everyone in **AI settings** and gives it to each user with the switch in **User management** (a switch in each user's row and a box in **Add user**). A user can use AI only when ai-service is connected, the feature is on, the user has it and it is not paused. **Pause** stops a running answer at once and keeps the user listed with their data.
  - The switch in User management appears only while ai-service is connected and the AI+ feature is on. Otherwise the rows show no AI+ line, a note under the page lead says why, and the server refuses to turn it on or off with **Turn on the AI+ feature in AI settings first.** (never a success message for a change that did not happen). Stored switches are kept. A paused user shows a **Paused** chip next to their switch.
  - The orange **AI+** badge shows next to the name of everyone who can use AI now. A dark **AI+** badge means the user has the feature but cannot use AI now (paused, the feature off or ai-service not connected; its tooltip says which, and a tap shows it on a touch screen; **Settings** → **Account** writes the reason out); no badge means no feature.
  - Users never see the name of the container: for them every outage reads **AI is not available right now. Try again later or ask an administrator.** Administrators see **ai-service is not connected right now.**
- **ai-service**: the AI runs as a third container of its own (folder `ai-service/`, image `xexam-ai-service`) with its own database in its own volume `xexam_ai_data`. It never receives sign-in cookies: Nginx asks the backend first and passes on only a short signed statement of who is asking. It is the only container with internet access; the backend still has none and never calls it. ai-service reports its state to the backend (at start, at once on a change, every 25 seconds and when it stops); after 60 seconds without a report the backend treats it as not connected. Xexam keeps working when it is stopped. The System log shows `AI: AI link: connected to the main service` once per reconnect and `AI: AI link: lost the main service` when the link breaks.
- **User management**: in **Add user** and **Change**, **Manage banks**, **Select all** and **Deselect all** sit in one row on top of the bank list, **Include banks imported later** is the first entry of the list, and the explanations are tooltips. **Manage banks** moved there from **Edit**.
- **Study records**: the row **Delete** button no longer wraps onto two lines on narrow windows.
- **New icon** for the app, the browser tab and the phone's home screen.
- **Configuration**: the optional `XEXAM_AI_SECRET_KEY` (the key that encrypts the saved AI keys; by default a key file in the AI volume), `XEXAM_INTERNAL_TOKEN` (the token between the backend and ai-service; by default a random one in the volume `xexam_link`), `XEXAM_AI_LOG` and `XEXAM_AI_SQLITE_JOURNAL`. Back up both data volumes from now on.
- **Database schema v5**: the new columns `users.ai_enabled` and `users.uid`; before the migration a copy is written to `<data dir>/backups/xexam-schema4-<date-time>.db`. ai-service keeps its own database `xexam-ai.db` (schema 2, with `users.function_enabled`, `users.free_mode`, `messages.free` and `usage.tokens_cached`); columns of schema 2 that a database from an earlier pre-release lacks are added automatically at start. Neither service opens the other's database.
- **New API**: `/api/ai/*`, answered by ai-service (`send` and `retry` stream their answer as server-sent events and take the reply language `lang`; a `free` in the body is ignored); `POST /api/ai/free` (administrators) and `freeMode` in `GET /api/ai/status`; `POST /api/ai/admin/suspend` and `resume`; `aiAllowed` in the signed-in user, `aiAvailable` (and for administrators `aiService`) in `/api/auth/state`, `ai`, `aiSuspended` and `aiAvailable` in `/api/users`, `/api/users/create` and `/api/users/update`; `tokensCached` in the usage; the internal `POST /internal/ai/heartbeat`.
- Tests: backend 316 → 342, frontend 139 → 246, AI service 160.

### v0.7.5 — 2026-11-11

**Fixes after v0.7: no more "Cannot reach the service" when several people use Xexam at once, real red for everything that deletes, green for every correct answer, and a shorter README with a separate usage guide. The database does not change.**

- **Too many requests**: Nginx now lets 30 API requests per second through from one address, with a burst of 120 (it was 10 with a burst of 30). Behind a tunnel such as Cloudflare Tunnel all users arrive from the tunnel’s one address and share this limit, and the System log page alone reads twice a second. When Nginx still refuses a request (429), the page retries a read twice by itself, then says **Too many requests**, instead of “Cannot reach the service” with a hint to sign in again. Uploads keep their own, smaller limit.
- **Red for deleting**: delete buttons, the confirm button of every delete dialog, error messages, form checks and the errors of the System log use GitHub’s red, in the light and the dark theme. Wrong answers stay orange, and warnings keep their own orange.
- **Green for every correct answer**: the **Correct** badge, the ticks of the result strip, the hotspot **Correct** tag and accuracies of 80 % and more in **Study records** are green like the correct options. On the **Your answer** line each letter of a multiple-choice answer is green or orange on its own, so a partly right answer shows both.
- **No question count in the public info**: `/api/info` no longer says how many questions there are (`bankCount` is gone); the route is public, and signed-in pages count the questions they may see themselves. It still reads the database, so the health check notices a broken one.
- **A shorter README**: installation, configuration, upgrading and this changelog. How to use Xexam, the Excel format and the import rules moved to `docs/en/usage.md`; everything else is in the other documents under `docs/`.
- **Screenshot tool**: `python tools/screenshots/retake.py` retakes every screenshot of the READMEs and docs, in all three languages, from a throw-away instance with made-up demo data, and cleans up after itself.
- **Fixes from the review of v0.7**:
  - an empty `XEXAM_LOG=` in `docker/.env` no longer hides every info and warning line: empty means `info`, and an invalid value falls back to `info` with one warning;
  - users that an older version added to a database of a v0.7 pre-release now get every bank when that database is converted, like the users of the upgrade;
  - on Home, a bank manager whose banks have only retired questions is sent to **Question banks**, where they can update their own banks;
  - the System log page gives up on a read after 10 seconds and tries again later;
  - the **Change** and **Unlock** buttons of User management have accessible names that contain their visible word;
  - the Excel format guide on the Question banks page matches the parser more closely (`HOTSPOT` is recommended, not required).
- Tests: backend 314 → 316, frontend 129 → 139.

### v0.7 — 2026-11-11

**Question banks per user, bank managers, a practice mode, the six-column Excel layout as the only one that can be imported, and a System log for administrators. The database moves to schema v4 automatically, after a backup copy is written, and now runs in WAL mode.**

- **Question banks per user**: in **User management** an administrator ticks, for each user, the existing question banks they see (with **Select all**) and, independently, **Include banks imported later**, which gives them every bank imported from then on. A new user sees no bank until some are chosen; every user from before v0.7 gets every existing bank and **Include banks imported later**, and administrators always see every bank. Taking a bank away keeps the user’s study records as history.
- **Bank managers**: a user with the new **Bank manager** permission (set in **User management**) can import new question banks and update or delete the banks they imported, but not the banks of administrators or other users. Users without it do not see **Question banks** in the menu, and opening the page directly shows **Not allowed**. Administrators see who uploaded each bank; when a user who uploaded banks is deleted, the banks move to the administrator who deletes them.
- **Practice mode**: **Start practice** next to **Start exam** on Home, with the same banks, sheets, count and order. Each question is checked at once (a single-choice question when you choose an option, the others with **Check answer**) and shows right or wrong, the correct answer, the explanation and the memory aid. A practice is saved as a study record of its own kind and counts in the wrong-answer notebook like an exam. **Study records** tags every record as **Exam** or **Practice** and can show only one kind, Home’s **Latest result** shows the latest record of either kind, and **Practise these** in the wrong-answer review now starts a practice.
- **Only the six-column Excel layout can be imported**: A English, B Chinese and C Japanese question; D English, E Chinese and F Japanese answer with explanation and memory aid. English is authoritative: the question type, the options, the hotspot items, the question identity and the answer key come from columns A and D. When the Chinese or Japanese answer differs from the English one, the row is imported with the English answer and the preview lists a warning. Files in the three- and four-column layouts are refused with a message, and every question imported from them earlier is retired at every start; the banks, the study records and the statistics stay. Update such a bank with the six-column version of its workbook: its questions are then recognised by their English text and start without answer history. The guide on the Question banks page explains only the six-column layout.
- **Answers and explanations in three languages**: every question card of the result page, an exam record and the wrong-answer review has its own **English** / **中文** / **日本語** switch for the question, the options, the explanation and the memory aid; the separate Chinese translation toggle is gone. Every question-language switch now says **English** / **中文** / **日本語** in every interface language.
- **Green and orange answers**: in the answers and explanations and in practice, the correct options are solid green and a wrongly chosen option is solid orange, with white text, in the light and the dark theme alike. Graded hotspot statements sit on a neutral background. On Home, **Start exam** is green and **Start practice** orange.
- **System log** (menu, administrators only): the last 2000 lines the backend logged since it started, read every half second, with **Pause**, **Jump to latest**, a level filter and a search. The lines name users by their username, never a typed name that has no account. Rejected requests and failed sign-ins that come in bursts are summed up once a minute, so they cannot push the other lines out. Older lines: `docker compose logs backend`.
- **SQLite WAL mode**: the database now runs in WAL mode (still with `synchronous=FULL`, so a committed change is not lost) and is checkpointed when the backend stops normally. A backup copied while the backend runs must include `xexam.db-wal` and `xexam.db-shm`, or stop the backend first. `XEXAM_SQLITE_JOURNAL=delete` in `docker/.env` keeps the old mode for unusual storage such as a network filesystem.
- **Time zone**: timestamps follow the host’s time zone by default (the compose file mounts the host’s `/etc/localtime`); a `TZ` set in `docker/.env` overrides it.
- **Configuration**: the compose files also pass `XEXAM_COOKIE_SECURE` and `XEXAM_LOG` from `docker/.env`. Log lines and the output of the command-line program are in English.
- **Sign-in and users**: the lock after wrong passwords is kept per account and cannot be worn away by guessing many other usernames; changing a password signs out your other sessions; **Unlock** is also offered while a user still has tries left, and the lock note is shown under the user’s row; User management counts each user’s study records (exams and practice).
- **Version file**: `VERSION` now holds `CODE_VERSION` (the version of the code, bumped together with this changelog) and `RELEASE_VERSION` (the last published release). The release job writes `RELEASE_VERSION` and the release badge at the top of the READMEs only after the images and the GitHub Release are published.
- **Database schema v4**: the new table `user_banks` and the new columns `users.new_banks`, `users.can_manage_banks`, `banks.owner_id` and `attempts.kind`; before the migration a copy is written to `<data dir>/backups/xexam-schema3-<date-time>.db`. A database written by a pre-release build of v0.7 is converted when it is opened, after a copy `xexam-schema4-<date-time>.db`.
- **New API**: `GET /api/logs` (administrators only); `banks`, `newBanks` and `canManageBanks` in `/api/users`, `/api/users/create` and `/api/users/update`; `kind` (`exam` or `practice`) in `/api/attempt`, `/api/records` and `/api/record`. `POST /api/upload` and `POST /api/import/confirm` refuse a three- or four-column workbook with 400. Only administrators see who owns a bank.
- Tests: backend 232 → 314, frontend 59 → 129.

### v0.6 — 2026-11-11

**Accounts and sign-in: every user has their own records, and administrators manage users and question banks. The database moves to schema v3 automatically, after a backup copy is written.**

- **Sign-in**: a standard sign-in page in the calm style of v0.5.1. On the first start (a new install or an upgrade) sign in with `admin` / `admin`; Xexam then asks for your own password, and the sign-in page and the startup log remind you until it is changed.
- **Users and roles**: administrators manage question banks and users; users take exams and see only their own study records, wrong-answer notebook, unfinished exam and settings. The question banks are shared. The data from before v0.6 belongs to the first administrator.
- **User management** (menu, administrators only): add, edit, reset the password of, disable / enable, delete and unlock users, with each user’s role, status (Normal, Disabled, Locked), created, last sign-in and number of exams. Users created or reset by an administrator choose their own password at the next sign-in.
- **Header**: your username (with **Admin** for administrators) left of the menu button; the menu shows only the pages of your role and ends with **Sign out**.
- **Settings**: a new **Account** section with **Change password**.
- **Wrong passwords**: 5 tries, then a lock of 1 minute; then 3 tries per round with locks of 5 minutes, 15 minutes, 30 minutes, 1 hour and 1 day. The sign-in page says how long to wait, and an administrator can unlock a user.
- **Security**: passwords as Argon2id hashes; `HttpOnly`, `SameSite=Strict` session cookies (the database keeps only their SHA-256), valid 30 days, signed out when the password, the role or the status changes. Plain HTTP keeps working (`Secure` only over HTTPS or with `XEXAM_COOKIE_SECURE=1`).
- **Locked out of the administrator account**: `docker compose exec backend xexam-backend reset-password admin` prints a new temporary password.
- **Database schema v3**: new tables `users`, `sessions`, `user_stats` and `user_settings` and the column `attempts.user_id`; before the migration a copy is written to `<data dir>/backups/xexam-schema2-<date-time>.db`.
- **New API**: `/api/auth/state`, `/api/auth/login`, `/api/auth/logout`, `/api/auth/password`, `/api/users`, `/api/users/create`, `/api/users/update`, `/api/users/password`, `/api/users/delete` and `/api/users/unlock`; every other route needs a signed-in account (`/api/info` stays public).
- **Repository layout**: the Japanese and Chinese READMEs moved to `README/`, the compose files and `.env.example` to `docker/` (in a clone, `.env` now goes to `docker/.env`). The README badges are rounded, and the release badge shows the version.
- Tests: backend 181 → 232, frontend 44 → 59.

### v0.5.1 — 2026-11-11

**A calmer, simpler look with colour-blind friendly colours, the menu button at the top right, and a Question banks page as compact as Home.**

- **A calmer, simpler look**: the colours now follow the colour-blind friendly light and dark palettes of GitHub's Primer design system ("Light colorblind" / "Dark colorblind"). Correct answers are blue and wrong answers orange instead of green and red. The light theme is a soft grey-white page with white blocks and navy main buttons; the dark theme is near-black. ### v0.3 — 2026-11-10

**The whole program was rewritten in Rust + TypeScript + Nginx. The database file and schema are unchanged, the API is backward compatible, and the old Python implementation has been removed from the repository.**

- **Backend rewritten in Rust** (Axum 0.8 + Tokio + rusqlite, toolchain pinned to 1.99.1): REST API, XLSX parsing, import (preview without writing to the database → one-time confirmation token → one-transaction write), score and wrong-answer statistics, Host/Origin guard, and the `xexam-backend import / healthcheck / migrate-progress` subcommands. Behavior matches the Python version one to one: all 172 legacy responses were compared item by item with no unexplained differences; the parse output of 49 synthetic workbooks and all 85 question id vectors are identical, so question ids are byte-for-byte the same as in the old version and learning records do not become detached.
- **Frontend rewritten in TypeScript** (strict) + **Vite**, plain DOM, no framework; there are no inline styles, so the CSP can be very strict. The build target is `safari15`, so iPhone needs iOS 15.4 or later.
- **Two images, two containers**: `xexam-frontend` (Nginx + static frontend files, the only one exposed) and `xexam-backend` (Rust, on the `internal` private network with no published port). Non-root, `cap_drop: ALL`, read-only root filesystem; Host passed through unchanged, `X-Forwarded-*` cleared; 20 MB limit, security headers, rate limiting, timeouts; a JSON 502 is returned when the backend is unreachable. Both images ship for `amd64` and `arm64`.
- **Stricter upload checks (intentional differences)**: DOCTYPE and entity declarations are rejected in any encoding / extension; duplicate ZIP entry names are rejected; there are limits on the number of ZIP entries, XML depth / node count / attributes per element, and total cell bytes; parsing has a cooperative timeout (the parser stops by itself when time is up) and at most 2 parses run at the same time; error messages no longer echo the library's exception text; unsupported HTTP methods return 405 (previously 501). See [docs/en/api.md](api.md) for the full table of differences.
- **One pipeline** (`.github/workflows/ci.yml`): check version and changelog → four check groups (frontend / backend / Nginx and full stack / arm64) → only if all pass, publish the two images and create the Release.
- **Tests**: 136 backend tests (against the committed legacy snapshot: 172 golden responses, 49 parse fixtures, 85 id vectors), 19 frontend tests; in `tests/integration/`, 38 Nginx checks, 34 full-stack checks and 10 `progress.json` migration checks.
- **Documentation**: architecture, API (including OpenAPI), database, security, deployment, migration and development under `docs/`, plus the pre-migration audit, risks and plan.
- Grading is still done in the browser (the server only receives `{id, correct}`, i.e. the question id and whether it was answered correctly); the reasoning is in [docs/zh-CN/history/migration-plan.md](../zh-CN/history/migration-plan.md).
- ⚠️ **Upgrade note**: the old and new containers have the same names and ports and **cannot run at the same time**, so run `docker compose stop` before upgrading; the data volume `xexam_data` is the same one, so no data migration is needed. The old single image `ghcr.io/yumin-space/xexam` is no longer updated (the last version was `v0.2.2`), and `docker-compose.yml` now pulls both `xexam-frontend` and `xexam-backend` at once. For rollback steps see [docs/en/migration.md](migration.md).
- **What has not been verified (stated honestly)**: a real Cloudflare Tunnel, a real iPhone, running on real ARM hardware (it was only built and started under QEMU), and a dry run with a copy of your own real database.

### v0.2 — 2026-11-10

  - Database: if `COMMIT` fails it rolls back instead of leaving the connection stuck in a transaction; a malformed old `progress.json` no longer keeps the program from starting; when the data directory contains only some other `.db` file, the startup log gives a warning (that file is not modified).
  - Pages: when submitting a quiz, the saved progress is cleared only after the score has been submitted successfully; on failure it is kept and a prompt `刷新页面重新登录后再交卷` ("Refresh the page, log in again, then submit") is shown; before starting a new exam, if there is an unsubmitted exam, it asks for confirmation first; the percentage on the result page uses the same rounding as the learning record and no longer differs by 1; the notification bar is no longer covered by the bottom paging bar; long English strings no longer cause a horizontal scrollbar; old Safari without `<dialog>` uses the system confirmation box; holding down a letter key no longer toggles the answer repeatedly.
