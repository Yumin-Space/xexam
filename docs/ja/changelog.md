### v0.9 — 2026-11-11

**AI+ 機能のあるアカウント向けに、学習中の AI サポート：練習中のヒントと解説、結果の AI 解析、間違えた問題の AI まとめ。3 つのイメージ、ボリューム、docker-compose.yml はそのままです。データベースは自動的に移行します（メインはスキーマ 6、AI はスキーマ 3）。どちらも、バックアップのコピーを書き出したあとです。**

- **表示される人**：**AI+ 機能** のあるアカウントだけです（AI+ 機能がオンの間の管理者。オレンジの **AI+** バッジ）。機能のないユーザーには、以下のコントロールはまったく表示されません。機能はあるものの今は AI を使えないユーザー（管理者が一時停止した、AI+ 機能がオフ、または ai-service に接続できない）には、コントロールが **使用不可** のタグ付きでグレーアウトされ、理由を示すツールチップ（タッチ画面ではタップで表示）が付き、学習記録では表の上に 1 行の注記が付きます。サーバーもこれらのリクエストを拒否します。試験の最中はこれらは何もありません。試験で AI を使えるのは、その結果ページと学習記録だけです。
- **練習**：すべての問題で、操作バーに 2 つのボタン **AI ヒント** と **AI 解説**、カードのヘッダーの言語の切り替えの隣に、同じ 2 つが電球と本のアイコンとして並びます。ボタンとアイコンは同じ動作をします。
  - **AI ヒント**：どれが正しいかを言わずに、問題の解き方と、その背景にある知識のポイントを示します。モデルへのリクエストに答えが含まれることはなく、それでも答えを明かしてしまったヒントは非表示になります（**このヒントは答えを明かしてしまったため非表示にしました。再生成してください。**）。この検査は、そうした言い方の多くを捉える安全策であって、すべてを捉えるわけではありません。
  - **AI 解説**：まず正解、その問題が問う知識、なぜそれが正しく、ほかの選択肢がなぜ間違いか。
  - 回答は、ボタンの隣の小さな閉じられるウィンドウに順に表示され（Esc、外側のクリック、**閉じる**、別の問題への移動で閉じる）、**コピー**、**再生成**、**AI チャットで開く** があります。同じものをもう一度開くと、保存済みの回答がすぐに表示されます。**再生成** は新しい回答を書き、失敗した、または非表示になった新しい回答は、前の回答をそのまま残します。回答は **設定** の言語です（別の言語で保存された回答にはその旨が表示されます）。
- **結果**：練習の結果、試験の結果、学習記録の詳細ページのすべての問題カードに **AI 解析**（判定の行のボタンと、カードのヘッダーの本のアイコン）があります。問題を解説し、間違えたときは、あなた自身の回答にも触れます。問題文は、カード自身の言語の切り替えに従います。
- 記録の **AI まとめ**：**学習記録**（新しい最初の列。1 行に 1 つのボタン）と **ホーム**（直近の結果の、**詳細を見る** と **すべての学習記録** の間）にあります。大きなウィンドウに、弱い知識のポイント、注意すべき点、これからそのような問題にどう取り組むか、そしてそれらの話題の簡単なまとめが表示されます。間違えた問題だけが対象で（未回答は含まれません）、最大 70 問、それより多いときはランダムに選ばれます。ウィンドウには、たとえば **間違えた 80 問からランダムに選んだ 70 問に基づいています。** と表示されます。**再生成** は新しいまとめを書き、ボタンをもう一度押すと保存済みのものが表示されます。間違えた問題のない記録や、問題ごとの詳細を保存していなかったバージョンで保存された記録では、ボタンが理由とともにグレーアウトされます。
- **一度に 1 つの回答**：1 つの回答の作成中に別のリクエストをすると、どれが実行中かが表示され（**第 3 問の AI ヒントはまだ作成中です。**）、**表示**（同じページにあるとき）と **それを止めてこちらを作成** が示されます。自動で止まるものはありません。学習の回答は、この枠を AI チャットと共有します。
- **AI チャットでは**：練習、試験、まとめのそれぞれに 1 つのチャットがあり、タイトルは `<開始時刻>-練習`、`<開始時刻>-試験`、または `<記録の日時>-AIまとめ` です（タイトルの言葉は画面の言語、時刻は ai-service のタイムゾーンに従います）。すべての回答が順にそこに入り、それぞれの問題が、ヒント、解説、または第 n 問の解析として示されます。練習ページのヒントと解説、その結果ページの解析は、その練習のチャットを共有します。学習の回答には **再試行** も **これを覚える** もありません。学習記録を削除しても、そのまとめのチャットは残ります。ほかのチャットと同じように、学習のチャットも保存期間に従い、ユーザーが削除でき、管理者に見えます。削除されたチャットの回答は、もう保存済みとしては示されません。
- **v0.9 より前に作られた記録** にはセッションキーがないので、そのような記録の詳細ページでの最初の AI 解析は、その記録専用のチャットを作り、記録の日時とその種類の接尾辞で名付けます。
- **AI プロバイダーに送られるデータ**：ヒントでは、表示している言語の問題とその選択肢。解説と解析では、さらに問題集の答えと解説、結果ページではあなた自身の回答。まとめでは、間違えた問題のそれぞれについて同じものです。メモリーのメモ、それまでのチャット、フリーモードは、これらのリクエストには関係しません。使用量は機能別に数えられ（AI 設定の **使用量** の **機能別**：AI チャット、AI ヒント、AI 解説、AI まとめ）、内容は決して含まれません。
- **上限**：学習の回答の開始は、AI チャットと同じ Nginx の制限に数えられます（ログインしたブラウザごとに、バースト 10 の後は 1 分に 20 回。そのときウィンドウは数秒待つよう伝えます）。学習のチャットはそれぞれ 1 つのチャットで、リクエストごとに 2 件のメッセージなので、既定の 1 チャットあたり 400 件のメッセージは、1 つの長い練習で約 200 回のリクエストです（管理者が変更できます）。
- **レイアウト**：スマートフォンでは操作バーは 2 行のままで（2 つの AI ボタンは短いラベルを保ち、ごく狭い画面ではアイコンだけ）、グレーアウトされたコントロールは、ページを広げずに言語の切り替えと一緒に折り返され、学習記録は狭いウィンドウではカードのレイアウトを保ち、各カードに AI まとめのボタンがあります。
- **データベースのスキーマ 6**（メインのデータベース）：`attempts.session_key` と `attempts.started_at`（NULL 可）。移行の前に、コピーが `<データのディレクトリ>/backups/xexam-schema5-<日時>.db` に書き出されます。**AI のデータベースのスキーマ 3**：`chats.kind`、`ref`、`record_id`。`messages.kind`、`question_id`、`question_no`、`source`、`lang`、`sample_used`、`sample_usable`、`sample_wrong`。`usage.purpose`（AI チャットでは空）。3 つのインデックス。先に、コピーが AI のボリュームの `backups/xexam-ai-schema2-<日時>.db` に書き出されます。バックアップは自動では削除されず、各アップグレードには、そのデータベースとほぼ同じ大きさのディスクの空き容量が必要です。v0.8 はスキーマ 6 のメインのデータベースをそのまま開けますが、その AI サービスはスキーマ 3 を拒否します：AI のデータベースのロールバックは、そのコピーを元に戻すことです。AI サービスは、保存期間を過ぎたチャットを少しずつ削除するようになりました。
- **新しい API**：`POST /api/ai/study/ask` と `POST /api/ai/summary/ask`（`send` と同じサーバー送信イベント）、`GET /api/ai/study/saved` と `GET /api/ai/summary/saved`。チャットのルートの、チャットの `kind` と `recordId`、メッセージの `kind`、`questionId`、`questionNo`、`source`、`lang`、`sample`、`start` イベントの `chatKind`、`ai.busy` の拒否の `running`、AI の使用量の `byPurpose`。`POST /api/attempt` は `key` と `startedAt` を受け取り、新しい記録の `recordId` を返し、`GET /api/record` は `sessionKey` と `startedAt` を返します。内部の `POST /internal/ai/question`、`/record`、`/record-info`（トークンのみ）。Nginx はリクエストのパスを記録しますが、クエリ文字列は記録しなくなりました。
- **リリースの署名**：リリースジョブは、リリースしたバージョン（`RELEASE_VERSION` と README のバッジ）を `git push` ではなく GitHub API で作ったコミットで記録するようになりました。GitHub がそのコミットに署名するので、**Verified** と表示されます。

### v0.8 — 2026-11-11

**AI チャットを ai-service という専用のコンテナで、新しいアイコン、よりコンパクトになった問題集のアクセス設定。AI は管理者が設定するまでオフです。新しい docker-compose.yml をダウンロードしてください：3 つ目のイメージ xexam-ai-service と 2 つのボリュームが加わります。データベースは、コピーを書き出したうえでスキーマ v5 へ自動的に移行します。**

- **AI チャット**（メニュー）：AI モデルとチャットできます。
  - 回答は書かれるそばから表示され（推論モデルがまだ考えている間は **考え中…** と表示）、ページを閉じても書き続けられて保存されます。**停止** と **再試行** があります。チャットは保存され、最後のメッセージから 90 日後に自動で削除されます（変更可能）。
  - AI は **設定** で選んだ言語で答えます（そのメッセージで別の言語を頼んだ場合を除く）。メモもその言語で書かれます。空の新しいチャットには、AI がどの言語で答えるかが表示されます。
  - チャットアプリのような固定の高さのウィンドウ：メッセージはその中でスクロールし（キーボードで移動・スクロールできる領域）、入力欄は下に残ります。すべてのメッセージに時刻と **コピー** があり、**これを覚える** と **再試行** はその下の 1 行に並びます。
  - アドレスが開いているチャットを保持します：チャットは `#/ai/<id>`、新しいチャットは `#/ai/new` なので、再読み込みしても同じチャットが開きます。
  - **メモリー** には、AI がその後のチャットで参考にする短いメモが入ります。メモは手動で、または **これを覚える** で追加します。上部の 1 行が、管理者はあなたの AI チャットとメモリーを閲覧・削除でき、AI の使用量も確認できることを伝えます。自分のチャットとメモリーは、AI+ 機能がオフのときや一時停止中でも、いつでも閲覧・削除できます。
  - AI を使えず、チャットもメモリーもないときでも、**AI チャット** は開き、理由（一時停止中、AI+ 機能が今は利用できない、またはアカウントに付与されていない）と対処を表示します。読み取り専用の **AI チャット** の上部の 1 行は、暗い色の **AI+** バッジのツールチップと同じ文です。
  - **フリーモード** は管理者のモードで、**設定** の **AI 対話モード**（**通常モード** / **フリーモード**。AI+ 機能がオンの間、管理者にだけ表示）で選びます。オンの間は、どのチャットのどのメッセージも（古いものも新しいものも）、学習アシスタントの指示、今日の日付、メモリーなしでモデルに送られ（返答言語のルールだけが残ります。プロバイダー自身の安全ルールは常に適用されます）、**AI チャット** のタイトルの隣に緑の **フリーモード** のタグが付きます。AI チャット自体にはスイッチも区切りもありません。選択はサーバーが保持するので、再読み込みや別の端末でも残ります。次のメッセージから適用され、既定ではオフです。すべてのメッセージが書かれたときのモードを記録し、切り替えの後は、モデルに現在のモードが短い 1 行で伝えられます。上限、使用量の統計、管理者のビューは通常どおりです。
  - **リクエストを安く**：プロバイダーは各リクエストの先頭をキャッシュすることがあります（Anthropic：指示と、新しい質問の前の履歴にキャッシュポイントを置きます。OpenAI 形式のプロバイダー：対応していれば自動でキャッシュします）。この先頭を安定させるため、履歴は毎回同じ方法で短縮されます：新しい 4 件のメッセージはそのまま、それより古い回答は 800 文字、古い質問は 2000 文字までに切り詰めます。
- **AI 設定**（管理者）：
  - ページは常に開きます。上部の 4 つのチップが設定の進み具合（**接続を保存済み**、**モデルを保存済み**、**テスト成功**、**AI+ 機能はオン**）を示し、1 行が ai-service が接続されているか（バージョン、最後の報告）を伝えます。新規インストールでは最初のチップが **接続が未設定** と表示され、接続を保存するまでモデル一覧は要求されません（チャットの保存期間だけを保存しても接続の保存にはなりません）。ai-service が接続されていないときは、**ai-service の接続状態** のパネルが原因（動いていない、停止した、接続していない、最初の報告待ち、またはメインサービス）を示し、10 秒ごとに再確認します。
  - OpenAI 互換 API、Anthropic、Cloudflare AI Gateway（その認証方式とキーも設定）。保存するとモデルが自動で、検索できる一覧になります。チャットモデルではなさそうなモデル（埋め込み、リランキング、安全分類、画像生成、音声、文書解析、画像専用）は、タグとヒント付きで最後に並びます。何も隠されません。キーの欄には **キーを表示** / **キーを隠す** のボタンがあります。
  - **AI+ 機能** は **テスト** に成功してからでないとオンにできません。オンの間に接続またはモデルを変えて保存すると、まず確認があり、その後全員に対してオフになります。新しいテストに通ってもう一度オンにするまでオフのままです（テストに成功しても自動でオンになることはなく、**テスト** の下の行はスイッチに従います）。キーは暗号化して保存され、二度と表示されません。保存したキーは、入力し直さない限り新しいアドレスへは送られません。
  - ユーザー別、モデル別、期間別の使用量の統計（既定は 7 日。呼び出し、入力・出力トークン、プロバイダーのキャッシュから返された **キャッシュ** トークン、エラー。内容は決して含みません）。
  - **AI+ ユーザー**（AI+ 機能を持つすべての人）：**利用中** または **一時停止中** を示す **AI+ 機能** の列と、**一時停止** と **再開** のボタン（ユーザー管理のスイッチは決して変わりません）、そしてチャットとメモリーの読み取り専用の表示（**削除** で消去もできます）。表示、削除、一時停止、再開はすべてシステムログに書き込まれます。900 px 未満では 2 つのトークンの列が省かれ（**使用量** にあります）、560 px 未満では各ユーザーが小さなカードになります。
  - チャットの保存期間（1〜3650 日）と **安全上限**（同時に作成する回答、チャット、メッセージ、メモ、メッセージの長さ）。安全上限はサーバーを守るためのもので、利用量の制限ではありません。
- **1 つの名前、ユーザーごとに 2 か所**：名前はどこでも **AI+ 機能** です。管理者は **AI 設定** で全員に対してオンにし、**ユーザー管理** のスイッチ（各ユーザーの行にスイッチ、**ユーザーを追加** にチェックボックス）で各ユーザーに付与します。ユーザーが AI を使えるのは、ai-service が接続されていて、機能がオンで、そのユーザーが機能を持ち、一時停止されていないときだけです。**一時停止** は作成中の回答をすぐに止め、ユーザーをデータごと一覧に残します。
  - ユーザー管理のスイッチは、ai-service が接続されていて AI+ 機能がオンの間だけ表示されます。そうでないときは、各行に AI+ の行はなく、ページの説明の下の注記が理由を伝え、サーバーはオンにもオフにも **先に AI 設定で AI+ 機能をオンにしてください。** で拒否します（起きなかった変更に成功のメッセージが出ることは決してありません）。保存されたスイッチはそのまま残ります。一時停止中のユーザーには、スイッチの隣に **一時停止中** のチップが表示されます。
  - オレンジの **AI+** バッジは、今 AI を使えるすべての人の名前の隣に付きます。暗い色の **AI+** バッジは、機能はあるが今は AI を使えない（一時停止中、機能がオフ、または ai-service に接続できない。ツールチップがどれかを示し、タッチ画面ではタップすると表示されます。**設定** → **アカウント** が理由を文で示します）ことを表し、バッジなしは機能なしを表します。

  - 拒否されたときは、どの条件を通らなかったのか、どう許可すればよいかが表示されます。ログインが期限切れになったときは、再読み込みして再ログインするよう画面に案内が出ます。
- ポートのバインドを設定可能にしました（`XEXAM_BIND`）。デフォルトは引き続きローカルのみのバインドです。
- `docker stop` の停止シグナルを受けると正常に終了するようになりました（以前は 10 秒待たされた末に強制終了されていました）。データベースもきれいに閉じられます。
- CI：「バージョンと更新履歴の検査 → 2 つのアーキテクチャそれぞれでテスト → 公開」の 3 段階に分割しました（v0.2.1 からは 4 段階目として Release の作成を追加）。スモークテストは `scripts/smoke-test.sh` に移し、ローカルに Docker があればそのまま実行できます。公開後はダイジェストでイメージマニフェストを照合します。
- `/api/info` に `arch`（現在の CPU アーキテクチャ）を追加しました。
- 監査後の修正（すべて実測による確認付き）：
  - サーバー：早い段階で拒否するリクエスト（403/415）は、リクエストボディを読み切ってから応答するようにしました。ブラウザには「サーバーに接続できません」ではなく本当の原因が表示されます。拒否されたリクエストはログに 1 行残ります（`docker compose logs` で確認できます）。不正な JSON（数値をリストとして渡す、`Infinity`、深すぎるネスト、非 ASCII の確認コード）には、接続を切るのではなく 400/409 を返します。POST の `Content-Type` は実際に `application/json` である必要があります。`XEXAM_ALLOWED_HOSTS` は、スペースやセミコロン区切りでも認識されます。
  - データベース：`COMMIT` に失敗したときはロールバックし、接続がトランザクション内に居座らないようにしました。形式が不正な古い `progress.json` があってもプログラムが起動しなくなることはありません。データディレクトリに別の `.db` ファイルしかない場合は、起動ログで知らせます（そのファイルには手を加えません）。
  - 画面：提出時は、成績の送信に成功してから一時保存を消すようにしました。失敗した場合は保存を残し、`刷新页面重新登录后再交卷`（「ページを再読み込みして再ログインしてから提出してください」）と表示します。新しい試験を始める前に、未提出の試験があれば確認を出します。成績画面のパーセンテージを学習記録と同じ丸め方にして、1 のずれが出なくなりました。通知バーが下部のページ送りバーに隠れなくなりました。長い英字列で横スクロールバーが出なくなりました。`<dialog>` のない古い Safari ではシステムの確認ダイアログを使います。英字キーを長押ししても答えが繰り返し切り替わらなくなりました。
  - イメージと CI：ヘルスチェックはプロキシを経由せず、`XEXAM_PORT` に従います。`.dockerignore` は階層を問わず有効になりました。`.gitignore` にバックアップ用の圧縮ファイルと `.env.*` を追加しました。公開は `main` からのみで、`main` で待機中のものはキャンセルしません。スモークテスト内のコンテナ内パスは、Windows の Git Bash でも動きます。
  - このバージョンは、ローカルで Docker を使って実際にイメージ（amd64）をビルドし、CI と同じスモークテストを通しました：非 root、Host/Origin の遮断、コンテナ削除後もデータが残ること、`docker stop` が 1 秒。arm64 と公開については、引き続き GitHub Actions の結果を確認する必要があります。
- 名称を **xexam** に統一しました：環境変数は `XEXAM_DATA` / `XEXAM_HOST` / `XEXAM_PORT` / `XEXAM_ALLOWED_HOSTS` / `XEXAM_ALLOWED_ORIGINS` / `XEXAM_ALLOW_ANY_HOST`、データベースファイルは `xexam.db`、ブラウザに保存するキー名は `xexam.*` です。ドキュメントにも、ご自身の Excel ファイル名を直接書かなくなりました。
- ⚠️ **v0.1 からのアップグレード時の注意：** データベースファイルの名前が変わり、新バージョンは `xexam.db` だけを読み込みます。それ以前のバージョンですでに問題集をインポートしている場合は、いったんプログラムを停止し、データディレクトリ内のその `.db` ファイルを `xexam.db` に改名してから起動してください。そうしないと問題集が空になります（古いファイルは削除されず、読み込まれないだけです）。ブラウザに一時保存していた試験や言語選択のキー名も変わったため、アップグレード前に提出を済ませてください。言語は日本語に戻ります。ご自身で変更した compose に古い環境変数名を設定している場合は、上記の `XEXAM_*` に書き換えてください。そうしないと無視されます。
