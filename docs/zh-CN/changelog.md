### v2.4 — 2026-11-22

**AI 生成题库和 AI 导入更可靠了：向 OpenAI 兼容的连接一次要完整的回答，用字母指代选项时改写而不是拒绝这道题，个别题做不出来也能完成题库，遇到等一等可能就会好的服务商错误会多等一会儿。主页一开始什么都不勾选，深色主题的卡片改成了蓝灰色。只改了 AI 服务和界面：数据库和变量都没有变化。升级：拉取镜像即可；回退到 v2.3.1 不需要还原。**

- **后台任务一次拿到完整回答**：AI 生成和 AI 导入现在向 OpenAI 兼容的连接一次要完整的回答（`"stream": false`），不再用流式，因为有些服务会不声不响地把流式回答截断。服务器仍然用流式回答时，照样读取。这种请求超时，或者代理返回网关超时（HTTP 504 或 524，比如会切断长时间没有数据的响应的代理）时，这个连接和模型的后台任务改回流式，直到 AI 服务重启。AI 对话始终是流式的，Anthropic 和 OpenAI Responses 格式也一样。
- **修正用字母指代选项**：解析里用字母指代选项（"Option B"、"选项B"、"C项"、"Ａが正しい"，也包括 "A and B"、"A、B项"、"AとB" 这样的并列）时，选项打乱顺序后就会指错。现在这类指代会被改写成同一种语言里加引号的选项文字，而不是拒绝这道题。"A项目"（项目 A）、"ビタミンCが正常" 这样的普通词语保持不变。"A. …"、"(B) …" 这样的标签，只有当这道题的每个选项都按顺序以自己的字母开头时才会去掉。AI 导入时，只修正由 AI 编写四个选项的题的解析；保留文件原有选项的题不做任何改动。
- **个别题卡住不再让生成失败**：AI 生成题库时，试了 5 次仍然通不过检查的题会被略过，任务继续。只要至少一半的题通过（比如 20 道里 19 道），就生成题库，完成的卡片上写着 **19 / 20 道题**，以及略过了几道。不到一半时，仍像以前一样失败，原因是通过检查的题不到一半；一旦已经不可能凑够一半（或者还没有一道题通过就有题被略过），任务马上停止，模型什么都给不出来时不会白白耗掉调用次数。AI 导入资料保持原来的规则（有题卡住时任务以质量错误结束），AI 导入题目仍然跳过失败 3 次的题。
- **服务商错误**：连续出错后，任务依次等待 15 秒、30 秒，之后每次 60 秒（以前每次多等 15 秒，最多 60 秒）。等一等可能就会好的错误（过载、限流、连不上、服务器错误）要**连续 6 次**（大约等了 4 分钟）才会停止任务；其他错误（超时、密钥、额度、找不到模型、请求被拒绝）仍是连续 3 次就停止。AI 生成和 AI 导入的每一步都按这个规则。
- **主页一开始什么都不勾选**：在 **开始考试或练习** 里，打开主页时不勾选任何题库或工作表，之后出现的题库也不会被勾选（以前一开始勾选所有工作表，AI 题库以外的新题库也会自动勾上）。请勾选要用的内容，或点 **全选**。
- **蓝灰色的深色主题**：卡片和面板是 #0E1117（以前是 #212121），浅色填充是 #1A2029，悬停是半透明的蓝灰色，选中的分段是 #2A313C，边线是 #6E7681。页面仍然是黑色，浅色主题除了 AI 对话的输入框以外不变。
- **AI 设置 › AI+ 用户**：用户名保持在一行内；太长的名字以 "…" 结尾，完整的名字在提示里（以前长名字会被折成很多短行）。
- **AI 设置 › AI 题库，手机上的最近任务**：打开任务详情的按钮留在卡片里面（以前会从右边伸出去，列表还能左右滑动）；略过的题号很多时会换行。
- **题库列表**：正在生成的题库的占位行（主页和题库管理）不再显示浏览器灰色的按钮背景，悬停高亮只在有鼠标的设备上出现。
- **AI 对话的输入框**：不再有边线，输入时也没有蓝色的焦点光晕。深色主题下，它靠自己的填充色（#1A2029）和黑色页面、#0E1117 的卡片区分开；浅色主题下，它是白色，带一层很淡的阴影，不再用灰色边框。在触屏上点发送后，键盘会收起，对话重新占满整个屏幕；消息保存后，输入框缩回成一行。用手指或鼠标删除对话（或全部对话）后，别的对话或 **新对话** 不会再被套上蓝色的焦点框；用键盘删除时，焦点仍会移到下一个对话。
- **实测**（测试环境）：生成 20 道题用了 5 到 8 次模型调用，以前是 23 到 37 次。

### v2.3.1 — 2026-11-22

**AI 服务的容器现在和另外两个一样，叫 `xexam-ai-service`。只是改了名字：数据库、变量和界面都没有变化。升级：拉取新镜像并运行 `docker compose up -d`；回退到 v2.3 也不需要还原。**

- **容器名**：AI 服务的容器原来叫 `ai-service`，现在叫 `xexam-ai-service`，与 `xexam-backend`、`xexam-frontend` 保持一致。Compose 的**服务名**仍是 `ai-service`，所以 `docker compose logs ai-service`、`docker compose exec ai-service …`、内部地址 `http://ai-service:8766` 和 `XEXAM_AI_UPSTREAM` 都不变。
- **升级时**什么都不用做：`docker compose up -d` 会把旧的 `ai-service` 容器换成新名字的容器。数据卷（`xexam_backend_data`、`xexam_ai_data`）不变。
- 按容器名调用 `docker logs ai-service` 或 `docker restart ai-service` 的脚本，现在要改成 `xexam-ai-service`。按服务名使用的 `docker compose` 命令照常可用。

### v2.3 — 2026-11-21

**AI 对话重新设计成聊天应用的样子：每次进入都是新对话，平板和电脑上有侧边栏，手机上有抽屉，顶栏也更整齐。只改了界面：服务器、数据库和变量都没有变化。升级：拉取镜像即可；回退到 v2.2 不需要还原。**

- **进入 AI 对话会新开一个对话**，任何宽度都一样。地址里的对话和还在生成的回答优先；AI+ 功能被暂停的用户会以只读方式打开最近的一个对话。
- **手机布局（窄于 720 px）**：页头是一行，有 **全部对话** 按钮（两条横线的菜单图标）、带 **自由模式** 标签的标题、**新对话** 按钮和用来删除这个对话的 **⋯** 菜单。抽屉从左边滑出（宽度取 320 px 和屏幕 82 % 中较小的一个），里面有搜索框、**新对话**、**记忆**、按 **今天**、**昨天**、**7 天内**、**更早** 分组的历史、每一行的 **⋯** 菜单、**删除全部对话**、保留时间的说明和 GitHub 那一行。点它背后的页面、按 Esc、向左滑、按返回键或选一个项目，它就会关上。
- **平板和电脑** 上始终显示同一个侧边栏。**对话** 和 **记忆** 两个标签页没有了：**记忆** 是侧边栏的一行，它的视图会替换对话。
- **空的新对话会显示一句问候。** 管理员的说明更短（手机上是一行），也不再放在抽屉里。**跳到最新** 只滚动，不再弹出键盘。强度按钮在每个等级下看起来都一样。地址里的对话已被删除或不存在时，会回到一个新对话，并显示一条简短的说明。
- **顶栏**：平板和电脑上又显示标志图标，手机上只有文字 **Xexam**。窄屏手机上文字调得很大时，名字先变小，只在万不得已时才省略。
- **重新设计的输入框。** 空的新对话里，问候和输入框在屏幕正中；发出第一条消息后，输入框落到底部，管理员说明始终在最底下。输入框下面的回答语言提示行没有了，输入框区域没有分隔线，背景和对话一样。输入框为空或很短时是一行紧凑的圆角条（大脑、输入、发送），文字要换行或有换行符时，展开成整宽文本加下面一行控件；最多长到 8 行（手机上是可见高度的 40 %），再往上在里面滚动，长单词在边缘折行，变短后会缩回去。手机上输入框是一行时，思考强度的选择是大脑选择器里的下拉框（在 API 和模型之后）；输入框展开后，以及在较宽的屏幕上，又是单独的强度按钮。**跳到最新** 不会再打开或关闭键盘。
- **所有页面改用新的深色主题**：纯黑页面（#000000），卡片、输入框、菜单和输入框区域是 #212121，控件是 #303030，白色文字和白色细线。浅色主题不变，有含义的颜色（考试绿、练习橙、答案颜色、AI+ 橙、危险红）也不变。
- **小修复**：文字调得很大时手机顶栏也放得下（名字变小，万不得已才省略）；主页的开始一行在横着拿的手机上也放得下；强度菜单在较矮的横屏里也留在屏幕内；答题卡的小方块有 44 px 可点。

### v2.2 — 2026-11-21

**什么都不发送的“默认”思考强度、AI 对话的强度按钮、服务器匀速发送默认每分钟 13 次请求 / 230 000 tokens，以及手机和电脑上的全站一致性整理。升级：拉取镜像即可；AI 数据库仍是 schema 11，先做一份备份副本，再一次性调整匀速发送的默认值；回退到 v2.1 不需要还原。**

- **思考强度“默认”**：**AI 设置 → 连接与模型** 里每个强度下拉框的第一项都是 **默认（不发送强度参数）**。从没动过的行也是默认：v2.1 在这里发送模型的默认强度，v2.2 什么都不发送。选其他强度时，仍照常发送对应参数。
- **AI 对话**：大脑按钮现在只选 **API** 和 **模型**，强度有旁边单独的按钮。它的菜单列出 **默认**、该连接家族的强度，以及对话有自己的选择时的 **跟随 AI 设置（当前：…）**。
- **匀速发送默认 13 次请求 / 230 000 tokens 每分钟**，任何地方都不再乘 0.9。升级时，仍是旧默认值的数值改成新默认值，你自己填的数值原样保留。仍是 v2.1 默认值 13 / 240 000 的 schema 11 文件，先备份，再一次性改成 13 / 230 000。
- **手机顶栏**：账户名隐藏，显示人形图标、**AI+** 徽章和简短的管理员标签，互不重叠。点账户按钮会显示一条提示，写着你的名字、角色和 AI+ 状态；菜单从 ≡ 按钮打开。电脑上不变。左上角的品牌是文字 **Xexam**（没有标志图标），始终不隐藏，顶栏在每个页面（包括 AI 对话）都在同一个位置。
- **练习 / 考试页也有主题按钮**：太阳 / 月亮按钮在这里也能用。
- **AI 题库标签页**：**最近的 AI 题库任务** 像 AI 用户标签页一样分页（搜索、排序、每页 10 条、最多 200 条），每个任务可以展开详情（类型、来源、方式、已生成 / 目标、调用、tokens、缓存 tokens、时间、状态 / 原因、生成的题库）。
- **手机与布局**：手机上的练习和考试里，选项字母在第一行开头，文字折行后回到最左边；回顾里的选项也一样。答题卡每次进入答题页都是收起的。主页上的 **开始考试** 和 **开始练习** 始终一样宽。AI 对话里给管理员的提示在手机上会折行，页脚的免责声明在一行放得下时居中。
- **一致性整理**：顶栏位置、标题字号、按钮高度和圆角、标签页和分段控件的高度、复选框大小、输入框高度（触屏输入框用 16 px 文字，iPhone 不会自动放大）、不小于 44 px 的触控区、菜单和对话框的外框、空状态文字、搜索框、计数行、处处写成“Xexam vX.Y”的版本号，以及中文、英文、日文的措辞和标点，都在每个页面按 375、393、768、1280 px 的宽度实测并统一。
- **单机 Docker Compose**：`docker-compose.yml` 和 `docker-compose.build.yml` 里写明了内部端口和地址（`.env` 里的 `XEXAM_BACKEND_PORT` 8765 和 `XEXAM_AI_PORT` 8766，Nginx 的上游地址跟着它们走）；后端和 ai-service 仍不对外发布端口。
- **数据库，AI**：没有 schema 变化（仍是 11）。一次性的匀速发送调整用 `meta.pace_default_230k` 标记。详见 [database.md](database.md) 的 8.2i 节和 [migration.md](migration.md) 的 v2.1 到 v2.2 一节。
- **回退**：v2.1 可以直接打开这个数据库，不需要还原。

### v2.1 — 2026-11-20

**思考强度按连接设置、AI Chat 选择器增加强度一步、顶栏明暗按钮，以及 iPhone 菜单的修复。升级：拉取镜像即可；AI 数据库启动时先写备份副本再升到 schema 11（回滚 = 恢复 `backups/xexam-ai-schema10-*.db`）；主数据库不变。**

- **思考强度跟着连接走**：每个连接有一个 **思考强度参数**（**Anthropic** `output_config.effort`、**OpenAI** `reasoning_effort`、**Google** `thinking_level`、**Responses API** `reasoning.effort`），在你手动选之前按连接的格式和地址自动决定。一个连接就是一个家族；一个网关服务多个厂商时，每个厂商加一个连接。连接卡片上会显示家族。
- **模型行**：**默认** 按钮和家族按钮都没有了。每行显示所用连接的家族图标和强度列表；没动过的行发送模型自己的默认强度（未知模型为 `medium`），所以每次调用都带强度参数。某个模型拒绝该参数，不再影响同一连接的其他模型。
- **总开关**：AI+ 关闭时，所有模型行变灰、不能操作（开关显示为关，已存的选择保留）；打开 AI+ 后恢复。
- **AI Chat 选择器**：自由模式下的管理员依次选 **API**、**模型**、**强度**（该连接家族的强度，模型默认有标记）。选择按对话记住；强度不是默认值时，大脑按钮上有一个小点。
- **顶栏**：名字左边的月亮／太阳按钮在深色和浅色之间切换，保存的选择与 **设置 → 外观** 相同。
- **iPhone 菜单修复**：在 AI Chat 里打开了一个对话时，点菜单项会停留在 AI Chat 的问题已修复。点按菜单项时还会显示按下的底色。
- **限额说明更清楚**：**AI 安全** 里每个上限都写明计什么：每用户请求次数上限计入对话消息、提示、解析、总结和记忆建议（不含出题和导入）；AI 出题和 AI 导入的最大调用次数作用于单个任务内部，对所有人包括管理员；**服务器** 页写明速率限制是服务商自己的限额，以及它限制哪些功能。
- **匀速发送按填写原样使用**：服务商速率限制不再被暗中扣掉 10%。新的默认值是每分钟 13 次请求、240 000 tokens。升级时，仍是旧默认值（15 / 250 000）的值变成 13 / 240 000，其他值乘以 0.9（至少 1 和 1 000），实际速度不变。
- **数据库，AI（schema 10 到 11）**：新增 `connections.effort_family`（根据提供方、格式和模型名推断，每个连接记一行日志）和 `chats.pick_effort`。与所属连接家族不符的已存强度会被清除（改用模型默认）。先写备份副本 `backups/xexam-ai-schema10-<日期时间>.db`。详情：[database.md](database.md) 的 8.2h 节和 [migration.md](migration.md) 的 v2.0 到 v2.1 一节。
- **回退**：v2.0 的 ai-service 拒绝 schema 11：把 `backups/xexam-ai-schema10-<日期时间>.db` 恢复到 AI 卷（升级之后写入的设置、对话和用量会丢失）。主数据库不用恢复。

### v2.0 — 2026-11-20

**数据库整理：主数据库加上外键，删除不再使用的旧表和旧列，新增索引；程序里看不出任何变化。升级：拉取镜像即可；启动时两个数据库各自先备份、再升到新的 schema（主库 10 到 11，AI 库 9 到 10）；请留出约两倍主数据库大小的空闲空间。回到 v1.9 需要 AI 备份 `backups/xexam-ai-schema9-*.db`，主数据库不用恢复。**

  - 当你不能使用 AI、又没有对话或记忆时，**AI 对话** 仍然能打开，并说明原因（已暂停、AI+ 功能暂时不可用，或你的账号没有开通）以及该怎么做。只读的 AI 对话顶部那一行，和深色 **AI+** 徽章的提示框是同一句话。
  - **自由模式** 是管理员自己的一种模式，在 **设置** 的 **AI 对话模式** 里选择（**普通模式** / **自由模式**；只有管理员在 AI+ 功能开启时才看得到）。开启后，任何对话（新的或旧的）里的每条消息，都会不带学习助手的指示、今天的日期和记忆发给模型（只保留回复语言规则；服务商自己的安全规则始终有效），**AI 对话** 标题旁边会有绿色的 **自由模式** 标记。AI 对话页面本身没有开关，也没有分隔线。服务器记住这个选择，所以刷新和换设备后都还在；它从下一条消息起生效，默认是关闭的。每条消息都记录它是在哪种模式下写的，切换之后，模型会用一句简短的话得知当前的模式。限制、用量统计和管理员的查看照常。
  - **更省的请求**：服务商可能缓存每个请求的开头部分（Anthropic：在指示和新问题之前的历史上设缓存点；OpenAI 格式的服务商在支持时自己缓存）。为了让这个开头保持稳定，历史总是用同样的方式缩短：最新的 4 条消息完整保留，更早的回答截到 800 个字符，更早的提问截到 2000 个字符。
- **AI 设置**（管理员）：
  - 页面总是能打开。顶部四个标记显示设置进行到哪一步（**连接已保存**、**模型已保存**、**测试成功**、**AI+ 功能已开启**），一行文字说明 ai-service 有没有连接（版本、最后一次报告）。全新安装时第一个标记是 **连接未设置**，在你保存连接之前不会请求模型列表（只保存对话保留天数不算连接）。没有连接时，**ai-service 连接状态** 面板会写明原因（没有运行、已停止、没有连接、在等它的第一次报告，或者主服务本身），并且每 10 秒重新检查一次；
  - OpenAI 兼容 API、Anthropic 或 Cloudflare AI Gateway（带它的认证方式和密钥）；保存后自动列出模型，放在一个可搜索的列表里。大概不是对话模型的模型（向量嵌入、重排序、安全分类、图像生成、语音、文档解析、仅图像）排在最后，带标签和提示；没有任何模型被隐藏。密钥输入框有 **显示密钥** / **隐藏密钥** 按钮；
  - 只有 **测试** 成功后才能开启 **AI+ 功能**。它开着时，保存改过的连接或模型会先询问，然后对所有人关闭它，并一直保持关闭，直到新的测试通过、你再把它开启（测试通过本身绝不会自动开启它；**测试** 下面那一行跟着开关变化）。密钥加密保存，以后不再显示，已保存的密钥不重新输入就绝不会发到新的地址；
  - 按用户、模型和时间统计的用量（默认 7 天；调用次数、输入和输出 Token、服务商从缓存里提供的 **缓存命中** Token，以及错误，从不包括内容）；
  - **AI+ 用户**（每个有 AI+ 功能的人）：**AI+ 功能** 一列显示 **使用中** 或 **已暂停**，带 **暂停** 和 **恢复** 按钮（它们从不改变用户管理里的开关），以及他们的对话和记忆的只读视图，可以用 **删除** 删掉；每次查看、删除、暂停和恢复都会写进系统日志。窗口窄于 900 px 时两列 Token 会省掉（它们在 **用量** 里）；窄于 560 px 时每个用户变成一张小卡片；
  - 对话保留（1 到 3650 天）和 **安全上限**（同时生成的回答数、对话数、消息数、记忆数、消息长度），它们用来保护服务器，不是用量限制。
- **每个用户两处设置，一个名字**：**AI+ 功能** 是各处统一的名字。管理员在 **AI 设置** 里为所有人开启它，并用 **用户管理** 里的开关把它开通给每个用户（每个用户那一行的开关，**添加用户** 里的勾选框）。只有 ai-service 已连接、功能已开启、用户有这个功能、而且没有被暂停时，用户才能使用 AI。**暂停** 会让正在生成的回答立即停止，用户仍然列在那里，数据也都保留。
  - 用户管理里的开关只在 ai-service 已连接、而且 AI+ 功能已开启时才出现。否则这些行里没有 AI+ 这一行，页面开头下面有一句说明原因，服务器也会拒绝开启或关闭它，提示 **请先在 AI 设置里开启 AI+ 功能。**（没有发生的修改绝不会提示成功）。已保存的开关保持不变。被暂停的用户，开关旁边会显示 **已暂停** 标记。
  - 每个现在能使用 AI 的人，名字旁边都有橙色的 **AI+** 徽章。深色的 **AI+** 徽章表示用户有这个功能，但现在不能使用 AI（被暂停、功能已关闭或 ai-service 没有连接；提示框里写着是哪一种，触屏上点一下就会显示；**设置** → **账户** 里会把原因写出来）；没有徽章表示没有这个功能。

- **ai-service**：AI 作为第三个容器单独运行（文件夹 `ai-service/`，镜像 `xexam-ai-service`），有自己的数据库，放在自己的卷 `xexam_ai_data` 里。它从不接收登录 Cookie：Nginx 先问后端，然后只把一份简短的、签过名的「是谁在请求」的声明传给它。它是唯一能上网的容器；后端仍然不能上网，也从不调用它。ai-service 把自己的状态报告给后端（启动时、有变化时马上、每 25 秒，以及停止时）；超过 60 秒没有报告，后端就认为它没有连接。它停止时 Xexam 照常可用。系统日志在每次重新连接时写一条 `AI: AI link: connected to the main service`，连接断开时写 `AI: AI link: lost the main service`。
- **用户管理**：在 **添加用户** 和 **更改** 里，**管理题库**、**全选** 和 **全部不选** 排成一行，放在题库列表上方，**包括以后导入的题库** 是列表的第一项，说明都改成了提示框。**管理题库** 从 **编辑** 移到了这里。
- **学习记录**：每一行的 **删除** 按钮在窄窗口里不再折成两行。
- **新图标**：用于程序、浏览器标签页和手机主屏幕。
- **配置**：可选的 `XEXAM_AI_SECRET_KEY`（加密已保存的 AI 密钥所用的密钥；默认是 AI 卷里的一个密钥文件）、`XEXAM_INTERNAL_TOKEN`（后端和 ai-service 之间的令牌；默认是卷 `xexam_link` 里的一个随机令牌）、`XEXAM_AI_LOG` 和 `XEXAM_AI_SQLITE_JOURNAL`。从现在起请备份两个数据卷。
- **数据库 schema v5**：新增列 `users.ai_enabled` 和 `users.uid`；迁移前会把副本写到 `<数据目录>/backups/xexam-schema4-<日期时间>.db`。ai-service 有自己的数据库 `xexam-ai.db`（schema 2，带 `users.function_enabled`、`users.free_mode`、`messages.free` 和 `usage.tokens_cached`）；早期预发布版本的数据库里缺少的 schema 2 的列，会在启动时自动补上。两个服务都不会打开对方的数据库。
- **新 API**：`/api/ai/*`，由 ai-service 响应（`send` 和 `retry` 以 server-sent events 流式返回回答，并接受回复语言 `lang`；请求体里的 `free` 会被忽略）；`POST /api/ai/free`（管理员）和 `GET /api/ai/status` 里的 `freeMode`；`POST /api/ai/admin/suspend` 和 `resume`；已登录用户里新增 `aiAllowed`，`/api/auth/state` 里新增 `aiAvailable`（管理员还有 `aiService`），`/api/users`、`/api/users/create` 和 `/api/users/update` 里新增 `ai`、`aiSuspended` 和 `aiAvailable`；用量里新增 `tokensCached`；内部的 `POST /internal/ai/heartbeat`。

### v0.7.5 — 2026-11-11

- CI：拆成「检查版本和更新日志 → 两种架构各自测试 → 发布」三步（v0.2.1 起再加第四步：建 Release）；冒烟测试挪进 `scripts/smoke-test.sh`，本机装了 Docker 也能直接跑；发布后按摘要核对镜像清单。

- 审计后的修复（每一条都有对应的实测）：
  - 服务端：提前拒绝的请求（403/415）先把请求体读掉再回复，浏览器看到的是真正的原因而不是「连不上服务」；被拒绝的请求在日志里留一行（`docker compose logs` 能看到）；畸形的 JSON（数字当列表、`Infinity`、过深嵌套、非 ASCII 的确认码）返回 400/409，而不是让连接断掉；POST 的 `Content-Type` 必须真的是 `application/json`；`XEXAM_ALLOWED_HOSTS` 用空格或分号分隔也能识别。
  - 数据库：`COMMIT` 失败时会回滚，不会让连接一直卡在事务里；格式不对的旧 `progress.json` 不再让程序起不来；数据目录里只有别的 `.db` 文件时，启动日志会提醒（不会改动那个文件）。
  - 页面：交卷时成绩提交成功才清掉暂存，失败会保留并提示「刷新页面重新登录后再交卷」；开始新考试前，如果有没交卷的考试会先确认；成绩页百分比与学习记录用同一种取整，不再差 1；提示条不再被底部翻页栏挡住；长英文串不再撑出横向滚动条；没有 `<dialog>` 的旧 Safari 改用系统确认框；长按字母键不会反复切换答案。
  - 镜像和 CI：健康检查不走代理并跟随 `XEXAM_PORT`；`.dockerignore` 改成任意层级生效；`.gitignore` 加了备份压缩包和 `.env.*`；只从 `main` 发布，`main` 上排队不取消；冒烟测试里容器内路径在 Windows 的 Git Bash 里也能跑。
  - 这版在本机用 Docker 真的构建了镜像（amd64），并用 CI 同一份冒烟测试跑通：非 root、Host/Origin 拦截、删除容器后数据还在、`docker stop` 1 秒。arm64 和发布仍要看 GitHub Actions 的结果。
- 名称统一成 **xexam**：环境变量 `XEXAM_DATA` / `XEXAM_HOST` / `XEXAM_PORT` / `XEXAM_ALLOWED_HOSTS` / `XEXAM_ALLOWED_ORIGINS` / `XEXAM_ALLOW_ANY_HOST`，数据库文件 `xexam.db`，浏览器里保存的键名 `xexam.*`；文档里也不再写死你自己的 Excel 文件名。
- ⚠️ **从 v0.1 升级时注意：** 数据库文件的名字变了，新版只读 `xexam.db`。如果你在更早的版本里已经导入过题库，请先停止程序，把数据目录里那个 `.db` 文件改名为 `xexam.db` 再启动，否则会看到空题库（旧文件不会被删，只是不会被读取）。浏览器里暂存的考试和语言选择用的键名也变了，升级前请先交卷，语言会恢复成日语。在自己改过的 compose 里设置过旧环境变量名的，要改成上面的 `XEXAM_*`，否则会被忽略。
